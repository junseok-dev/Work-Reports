1. 역할별 같은 본문, 다른 관리 권한

강사는 기수 허브의 수강생 평가 → 진단리포트에서 진입한다. 운영은 같은 하위 탭과 기존 진단 리포트(매니저) 상위 탭이 동일한 관리 컴포넌트를 연다. 진단 본문은 공유하지만 저장 대상과 발송 권한은 분리한다.

강사

담당 기수에서 수강생을 먼저 선택하고 해당 학생의 주차별 진단 근거를 확인한다. 제안 초안을 바탕으로 강사 피드백을 수정·저장한다.

운영

기수의 주간 리포트를 관리한다. 학생별 진단과 저장된 강사 피드백을 읽기 전용으로 확인하고, 선택한 주차의 DRAFT 강사 피드백을 일괄 발송한다. 운영이 별도 피드백을 작성하거나 저장하지 않는다.

수강생

BE 알림 서비스가 개인별로 생성한 알림을 받고 본인 주간 리포트로 진입한다. 다른 학생의 진단·강사 메모·미발송 초안은 볼 수 없다.

2. 수강생 우선·주차 사이드 탭

기본 구성은 강사와 운영이 같다. 수강생을 먼저 드롭다운으로 선택하면 그 학생에게 실제로 존재하는 주차가 왼쪽 사이드 탭으로 연속 표시되고, 오른쪽에 선택 주차 상세가 열린다.

3. 화면 필드와 요청 매핑

FE 조회 순서는 기수 수강생 목록 → 선택 학생의 주차 목록 → 학생·주차 상세다. 원천 GOV-AI 필드는 BE가 camelCase 화면 계약으로 변환한다.

화면BE 응답 필드원천/저장 필드처리 원칙

운영 피드백 필드는 두지 않는다. draftCount와 sentCount는 선택 학생 개인 수가 아니라 해당 기수·주차의 운영 발송 집계이며, 운영 일괄 발송 버튼 상태와 결과 갱신에 쓴다.

4. 원천 데이터와 LMS 저장 데이터의 분리

GOV-AI의 주간 분석 결과는 진단 본문과 제안 초안의 재료다. 강사 수정본·발송 상태·알림은 LMS 업무 데이터이므로 별도로 저장한다.

데이터원천/책임화면 사용
주간 진단 본문GOV-AI history/weekly 적재본level, confidence, gradeRationale, weakPatterns, riskFlags, recommendationsForInstructor, metrics
제안 초안GOV-AI suggested_feedback_draftBE가 suggestedFeedbackDraft로 변환. 강사 저장본이 없을 때 편집 초기값
강사 피드백LMS 강사 저장본강사 편집 재진입 값, 운영 읽기 전용 확인, 운영 일괄 발송 본문
발송·알림LMS BE 알림 서비스운영 일괄 요청을 학생별 개인 알림과 수강생 리포트 노출 상태로 반영

FE는 GOV-AI API를 직접 호출하지 않는다. API 키를 브라우저에 노출하지 않고, 같은 주차의 서로 다른 관측본을 섞지 않으며, BE가 적재·권한·식별자 매핑을 책임진다.

원천 제안 초안은 발송물이 아니다. 강사가 수정·저장한 LMS 피드백만 운영 관리 대상이며, 운영의 일괄 발송을 거쳐야 수강생 알림과 본인 리포트에 반영된다.

5. 학생별 진단·주차 관리 흐름

  1. 수강생 선택: 역할이 조회 가능한 기수 수강생 목록을 받고 studentUuid를 선택한다.
  2. 주차 표시: 선택 학생의 완료된 주차 목록을 받고 최신 주차부터 왼쪽 사이드 탭으로 나열한다.
  3. 상세 확인: 선택 학생·주차의 진단 본문과 제안 초안, 저장된 강사 피드백을 한 번에 받는다.
  4. 강사 수정·저장: 저장본이 없으면 suggestedFeedbackDraft를 textarea value로 사용한다. 수정 후 PUT으로 저장하며 상태는 DRAFT다.
  5. 운영 확인: 운영은 같은 학생 선택·주차 사이드 탭·진단 본문과 강사 저장본을 읽기 전용으로 본다.
  6. 운영 일괄 발송: 현재 선택 주차를 POST한다. BE가 해당 기수·주차의 모든 DRAFT 강사 피드백을 조회해 수강생별 알림을 만들고 SENT로 변경한다.

반드시 구분할 화면 상태

  • 기수 수강생 없음 / 수강생 목록 호출 실패 / URL의 학생이 허용 목록에 없음.
  • 선택 학생의 주차 없음 / 주차 목록 호출 실패 / URL의 주차가 해당 학생에게 없음.
  • 상세 호출 실패 / 일부 지표 null / 제안 초안 없음 / 강사 저장본 없음.
  • 강사 저장 중·실패·완료와 운영 발송 중·부분 성공·전체 성공을 구분한다.
  • 운영 일괄 발송은 해당 주차 draftCount가 1 이상일 때만 활성화한다.

기존 수강생 본인 API /student/course/diagnosis/my-reports[/{week}]에는 다른 학생 식별자를 붙이지 않는다. 지도자 화면은 전용 경로와 권한 검사를 사용한다.

6. 구현 상태와 남은 경계

확정한 화면 방향

  • 수강생을 먼저 선택하고, 선택 학생의 주차를 왼쪽 사이드 탭으로 모두 표시한다.
  • 강사와 운영은 같은 선택 구조와 진단 본문을 사용한다.
  • suggestedFeedbackDraft는 강사 저장본이 없을 때 강사 편집 입력의 초기값이다.
  • 강사만 피드백을 수정·저장하고, 운영은 읽기·주차 관리·일괄 발송만 한다.

FE 구현

브랜치 feat/staff-diagnosis-request-contract에서 운영·강사 source 분기, 수강생 목록·학생별 주차 목록·상세의 3단계 query, 강사 피드백 저장 mutation, 운영 주차 일괄 발송 mutation을 구현했다. 선택 학생과 주차는 diagnosisStudent·diagnosisWeek 쿼리로 보존한다.

운영의 기존 상위 진단 탭과 수강생 평가 하위 진단 탭은 같은 운영 API 관리 화면을 사용한다. 강사 화면은 강사 API를 사용하며, API 응답은 Zod 경계에서 검증한다.

7. BE 담당자 전달용 API 계약안

아래 API는 2026-09-08 현재 존재하지 않는 구현 요청안이다. FE는 이 경로와 camelCase 응답을 기준으로 연결했다.

역할·메서드제안 경로요청/응답
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students수강생 배열: studentUuid, name, reportCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports주차 배열: week, baseDate, endDate, feedbackStatus, draftCount, sentCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}진단 상세 + suggestedFeedbackDraft + instructorFeedback
강사 PUT/instructor/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/instructor-feedback{"content":"강사가 수정한 값"}. 저장 후 DRAFT
운영 POST/admin/cohorts/{cohortId}/diagnosis/reports/{week}/instructor-feedbacks/sendbody 없음 → requestedCount, sentCount, skippedStudentUuids

강사 저장 request 매핑

  • cohortId: 현재 강사 허브의 경로 파라미터.
  • studentUuid: 첫 GET에서 고른 수강생 드롭다운 value. 이름을 보내지 않는다.
  • week: 두 번째 GET이 반환한 기수 주차 정수. ISO 주차 문자열을 보내지 않는다.
  • content: textarea 현재 문자열. 초기값은 instructorFeedback.content ?? suggestedFeedbackDraft ?? ""다.
PUT /instructor/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/instructor-feedback
Content-Type: application/json

{
  "content": "강사가 검토 후 수정한 피드백"
}

권한·저장·알림 요구

  • admin/manager는 허용된 운영 범위, instructor는 JWT의 담당 기수만 조회·저장한다.
  • cohortId·studentUuid·week 소속을 서버에서 재검증하고 이름으로 저장하지 않는다.
  • content는 trim 후 1~1000자. 강사가 수정 저장하면 같은 학생·주차 저장본을 갱신하고 DRAFT로 되돌린다.
  • admin 상세 GET도 같은 instructorFeedback을 반환한다. 운영 전용 피드백 필드는 필요 없다.
  • 운영 일괄 POST는 body의 학생 목록을 신뢰하지 않고 해당 기수·주차의 최신 DRAFT 저장본 전체를 서버가 조회한다.
  • 수강생마다 별도 알림 레코드와 진단리포트 링크를 생성하며, 같은 피드백 버전 재요청은 중복 알림을 만들지 않는다.
  • 이미 SENT이거나 저장본이 없는 학생은 skippedStudentUuids로 반환한다.

현행 BE와의 차이

현행은 수강생 본인용 GET 2개와 운영 수집용 POST만 있다. 본인용 GET은 토큰 userId만 사용하므로 지도자 조회에 재사용하면 안 된다. 현행 WeekDetail에는 riskFlags, recommendationsForInstructor, suggestedFeedbackDraft, instructorFeedback, analyzedAt가 없어 확장이 필요하다.

실명·식별자는 비식별 예시만 사용한다. 이 문서의 운영·강사 API는 2026-09-08 기준 BE에 아직 없으며 구현 요청 계약이다.
