1. 같은 진단 본문, 역할별 공개·관리 경계

강사와 운영은 기수 허브의 수강생 평가 → 진단리포트에서 같은 학생별 관리 화면을 사용한다. 수강생은 대시보드 모달에서 같은 핵심 진단 본문을 읽되 내부 판정 신뢰도와 지도자용 정보, 미발송 피드백은 보지 않는다.

강사

담당 기수의 수강생·주차를 선택하고 수준·확신도·근거·지표·지도 제안을 확인한다. AI 원문을 참고해 피드백을 역할 전용으로 임시저장하거나 저장 완료해 운영에 알린다.

운영

강사 저장 알림과 저장 완료본·기존 발송본을 확인한다. 운영도 피드백을 수정·임시저장·저장할 수 있고, 현재 학생·주차 재분석과 선택 주차의 발송 대기본 일괄 발송을 수행한다.

수강생

본인의 완료 주차 리포트와 운영이 발송한 최종 피드백만 읽는다. 결측 지표는 —와 안내로 구분하지만 확신도, 위험 신호, 지도 제안, AI 원문, 임시저장본·저장 대기본은 공개하지 않는다.

AI 원문과 임시저장본은 발송물이 아니다. 강사 또는 운영이 저장 완료한 최신 LMS 피드백만 발송 대기 대상이며, 운영의 일괄 발송을 거친 publishedFeedback만 수강생 리포트에 반영된다.

5. 학생별 진단·피드백 관리 흐름

  1. 수강생 선택: 역할이 조회 가능한 기수 수강생 목록을 받고 studentUuid를 선택한다.
  2. 주차 표시: 선택 학생의 완료 주차를 받고 최신 주차부터 왼쪽 사이드 탭으로 나열한다.
  3. 상세 확인: 선택 학생·주차의 공통 진단 본문과 교직원 확인 정보, AI 원문, 피드백 세 상태를 함께 받는다.
  4. 임시저장: 강사·운영이 PUT .../feedback/draft로 현재 역할 전용 작업본을 보관한다. 다른 역할과 수강생에게는 보이지 않는다.
  5. 저장 완료: 강사·운영이 POST .../feedback/submit으로 공유 저장본을 갱신한다. 강사 저장은 운영 알림을 만들고, 최신 저장본은 READY_TO_SEND가 된다.
  6. 운영 재분석: 운영만 현재 학생·주차 재분석을 요청하고 성공 후 해당 상세를 다시 조회한다.
  7. 운영 일괄 발송: 선택 주차를 POST한다. BE가 해당 기수·주차의 발송 대기 저장본을 조회해 수강생별 공개본·알림을 만들고 SENT로 변경한다.
  8. 수강생 열람: 본인 상세 응답의 sentAt이 있는 피드백만 화면에 표시한다. 저장 중인 초안과 발송 대기본은 싣지 않는다.

반드시 구분할 화면 상태

  • 기수 수강생 없음 / 수강생 목록 호출 실패 / URL의 학생이 허용 목록에 없음.
  • 선택 학생의 주차 없음 / 주차 목록 호출 실패 / URL의 주차가 해당 학생에게 없음.
  • 상세 호출 실패 / 일부 지표 null / AI 원문 없음 / 임시저장본·저장 완료본·발송본 없음.
  • 피드백 임시저장·저장·재분석·일괄 발송 각각의 진행 중·실패·완료를 구분한다.
  • 운영 일괄 발송은 해당 주차 readyCount가 1 이상일 때만 활성화한다.

수강생 본인 API /student/course/diagnosis/my-reports[/{week}]에는 다른 학생 식별자를 붙이지 않는다. 지도자 화면은 전용 경로와 서버 권한 검사를 사용한다.

6. FE 구현 상태와 남은 경계

현재 반영된 화면 방향

  • 운영의 별도 상위 진단 탭을 제거하고 수강생 평가 하위 진단리포트로 통합했다. 구 주소는 통합된 하위 탭으로 이어진다.
  • 수강생을 먼저 선택하고, 선택 학생의 완료 주차를 왼쪽 사이드 탭으로 표시한다.
  • 수강생·강사·운영이 핵심 진단 본문을 공유한다. 수강생은 확신도를 숨기고, 강사·운영은 확신도와 교직원 확인 정보를 함께 본다.
  • 수강생 본인 상세에는 운영이 발송한 피드백만 노출한다. 미발송 초안과 저장 대기본은 노출하지 않는다.
  • 강사와 운영 모두 피드백을 임시저장·저장할 수 있다. 임시저장본은 역할별로 분리하고 저장 완료본은 공유한다.
  • 강사 저장 시 운영 알림을 표시하며, 운영만 현재 주차 재분석과 선택 주차 일괄 발송을 수행한다.

FE 계약과 로컬 검증 경로

현재 FE는 운영·강사 source 분기, 수강생 목록·학생별 주차 목록·상세의 3단계 query, 역할별 임시저장·저장 mutation, 운영 재분석·일괄 발송 mutation을 갖는다. 응답은 Zod 경계에서 검증하고 저장·발송 성공 뒤 관련 지도자 query와 수강생 본인 리포트 query를 갱신한다.

로컬 MSW는 수강생·강사·운영 조회와 전체 피드백 상태 전이를 한 흐름으로 재현한다. 강사와 운영의 임시저장본은 분리하고, 저장 완료본·운영 알림·발송본은 공유한다. VITE_REAL_DIAGNOSIS=true이면 이 handler를 등록하지 않아 동일 경로를 실서버로 보내며, 실패 시 mock으로 재시도하지 않는다.

자동화 검증이 다루는 범위

  • 수강생 본문에서 확신도 미노출, 강사·운영 본문에서 확신도 노출
  • 수강생 상세에서 sentAt이 있는 발송본만 표시
  • 강사 임시저장본의 운영 비공개와 저장 완료 후 운영 알림
  • 운영의 피드백 수정·임시저장·저장, 재분석, 발송 대기본 일괄 발송
  • 일괄 발송 전 수강생 비공개, 발송 후 공개본 반영

현재 상태: FE 화면·요청 계약·상태형 로컬 mock 반영 · 지도자용 BE 조회·임시저장·저장·재분석·일괄 발송 API와 알림 fan-out 구현 대기 · 실서버 통합 검증과 배포는 후속 단계다.

수강생 본인 상세의 피드백 경계

GET /student/course/diagnosis/my-reports/{week}의 instructorFeedback은 content, authorName, updatedAt, sentAt만 가진다. sentAt이 없거나 객체가 없으면 FE는 피드백 블록을 표시하지 않는다. 지도자용 temporaryDraft·savedFeedback·알림 상태는 절대 포함하지 않는다.

권한·저장·알림 요구

  • admin/manager는 허용된 운영 범위, instructor는 JWT의 담당 기수만 조회·저장한다.
  • cohortId·studentUuid·week 소속을 서버에서 재검증하고 이름으로 저장하지 않는다.
  • content는 trim 후 1~1000자다. 임시저장본은 역할별로 분리하고, 저장 완료 시 해당 역할의 임시저장본을 비운다.
  • 저장 완료본에는 authorRole을 남긴다. 강사 저장이면 managerNotifiedAt을 갱신하고, 운영 저장이면 새 강사 알림으로 취급하지 않는다.
  • 재분석은 운영만 가능하며 성공한 학생·주차 상세의 analyzedAt과 진단 결과를 갱신한다.
  • 운영 일괄 POST는 body의 학생 목록을 신뢰하지 않고 해당 기수·주차의 최신 발송 대기본 전체를 서버가 조회한다.
  • 수강생마다 별도 공개본과 알림 레코드를 생성하며, 같은 피드백 버전 재요청은 중복 알림을 만들지 않는다.
  • 발송 대기본이 없거나 이미 최신본이 발송된 학생은 skippedStudentUuids로 반환한다.

현행 BE와의 차이

수강생 본인용 주차 목록·상세 계약은 FE에 연결되어 있다. 반면 지도자용 학생 목록·학생별 주차·상세와 역할별 임시저장·저장, 운영 재분석·일괄 발송은 별도 구현이 필요하다. 로컬 MSW 동작은 계약 시연용이며 BE 구현 완료의 증거가 아니다.

실명·식별자는 비식별 예시만 사용한다. 수강생 본인 조회 계약과 지도자용 관리 계약은 분리하며, 지도자용 API는 2026-09-09 현재 BE 구현 요청안이다.
