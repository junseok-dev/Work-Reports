1. 같은 진단 본문, 역할별 공개·관리 경계

강사와 운영은 기수 허브의 수강생 평가 → 진단리포트에서 같은 학생별 관리 화면을 사용한다. 수강생은 대시보드 모달에서 같은 핵심 진단 본문을 읽되 내부 판정 신뢰도와 지도자용 정보, 미발송 피드백은 보지 않는다.

강사

담당 기수의 수강생·주차를 선택하고 수준·확신도·근거·지표·지도 제안을 확인한다. AI 제안 초안을 참고해 피드백을 역할 전용으로 임시저장하거나 저장 완료해 운영에 알린다.

운영

강사 저장 알림과 저장 완료본·기존 발송본을 확인한다. 운영도 피드백을 수정·임시저장·저장할 수 있고, 재분석 버튼과 선택 주차의 발송 대기본 일괄 발송을 사용한다. 재분석은 현재 mock 시각 갱신만 동작한다.

수강생

본인의 완료 주차 리포트와 운영이 발송한 최종 피드백만 읽는다. 결측 지표는 —와 안내로 구분하지만 확신도, 위험 신호, 지도 제안, AI 제안 초안, 임시저장본·저장 대기본은 공개하지 않는다.

2. 수강생 우선·주차 사이드 탭

강사와 운영은 수강생을 먼저 드롭다운으로 선택한다. 그 학생에게 실제로 존재하는 주차가 왼쪽 사이드 탭에 최신순으로 표시되고, 오른쪽에는 수강생 본문과 교직원 확인 정보·피드백 관리가 이어진다.

FE는 GOV-AI API를 직접 호출하지 않는다. API 키를 브라우저에 노출하지 않고, 같은 주차의 서로 다른 관측본을 섞지 않으며, BE가 적재·권한·식별자 매핑을 책임지는 구조가 필요하다.

AI 제안 초안과 임시저장본은 발송물이 아니다. 강사 또는 운영이 저장 완료한 최신 LMS 피드백만 발송 대기 대상이며, 운영의 일괄 발송을 거친 publishedFeedback만 수강생 리포트에 반영한다.

5. 학생별 진단·피드백 관리 흐름

  1. 수강생 선택: 역할이 조회 가능한 기수 수강생 목록을 받고 studentUuid를 선택한다.
  2. 주차 표시: 선택 학생의 완료 주차를 받고 최신 주차부터 왼쪽 사이드 탭으로 나열한다.
  3. 상세 확인: 선택 학생·주차의 공통 진단 본문과 교직원 확인 정보, AI 제안 초안, 피드백 세 상태를 함께 받는다.
  4. 임시저장: 강사·운영이 PUT .../feedback/draft로 현재 역할 전용 작업본을 보관한다. 다른 역할과 수강생에게는 보이지 않는다.
  5. 저장 완료: 강사·운영이 POST .../feedback/submit으로 공유 저장본을 갱신한다. 강사 저장은 운영 알림을 만들고 최신 저장본은 READY_TO_SEND가 된다.
  6. 운영 재분석: 운영만 선택 학생·선택 주차 재분석을 요청한다. 현재 mock은 analyzedAt만 바꾸며 실제 재분석은 하지 않는다.
  7. 운영 일괄 발송: 선택 주차를 POST한다. BE가 해당 기수·주차의 발송 대기 저장본을 조회해 수강생별 공개본·알림을 만들고 SENT로 변경한다.
  8. 수강생 열람: 본인 상세 응답의 sentAt이 있는 피드백만 화면에 표시한다. 저장 중인 초안과 발송 대기본은 싣지 않는다.

반드시 구분할 화면 상태

  • 기수 수강생 없음 / 수강생 목록 호출 실패 / URL의 학생이 허용 목록에 없음
  • 선택 학생의 주차 없음 / 주차 목록 호출 실패 / URL의 주차가 해당 학생에게 없음
  • 상세 호출 실패 / 일부 지표 null / AI 제안 초안 없음 / 임시저장본·저장 완료본·발송본 없음
  • 피드백 임시저장·저장·재분석·일괄 발송 각각의 진행 중·실패·완료
  • 운영 일괄 발송은 해당 주차 readyCount가 1 이상일 때만 활성화

수강생 본인 API /student/course/diagnosis/my-reports[/{week}]에는 다른 학생 식별자를 붙이지 않는다. 지도자 화면은 전용 경로와 서버 권한 검사를 사용한다.

6. FE 구현 상태와 남은 경계

현재 반영된 화면 방향

  • 운영의 별도 상위 진단 탭을 제거하고 수강생 평가 하위 진단리포트로 통합했다. 구 주소는 통합된 하위 탭으로 이어진다.
  • 수강생을 먼저 선택하고, 선택 학생의 완료 주차를 왼쪽 사이드 탭으로 표시한다.
  • 수강생·강사·운영이 핵심 진단 본문을 공유한다. 수강생은 확신도를 숨기고, 강사·운영은 확신도와 교직원 확인 정보를 함께 본다.
  • FE 계약·로컬 mock의 수강생 본인 상세에는 운영이 발송한 피드백만 노출한다. 현재 BE 상세에는 이 피드백 필드가 아직 없다.
  • 강사와 운영 모두 피드백을 임시저장·저장할 수 있다. 임시저장본은 역할별로 분리하고 저장 완료본은 공유한다.
  • 강사 저장 시 운영 알림을 표시하며, 운영만 재분석 버튼과 선택 주차 일괄 발송을 사용한다. 재분석 버튼의 “현재 주차”는 달력상 현재 주차가 아니라 화면에서 선택한 주차다.

FE 계약과 로컬 검증 경로

현재 FE는 운영·강사 source 분기, 수강생 목록·학생별 주차 목록·상세의 3단계 query, 역할별 임시저장·저장 mutation, 운영 재분석·일괄 발송 mutation을 갖는다. 응답은 Zod 경계에서 검증하고 저장·발송 성공 뒤 관련 지도자 query와 수강생 본인 리포트 query를 갱신한다.

로컬 MSW는 수강생·강사·운영 조회와 전체 피드백 상태 전이를 한 흐름으로 재현한다. 강사와 운영의 임시저장본은 분리하고, 저장 완료본·운영 알림·발송본은 공유한다. VITE_REAL_DIAGNOSIS=true이면 이 handler를 등록하지 않아 동일 경로를 실서버로 보내며, 실패 시 mock으로 재시도하지 않는다.

재분석은 아직 시연 동작이다. 로컬 mock은 선택 학생·선택 주차의 analyzedAt만 클릭 시각으로 바꾼다. 등급·근거·위험 신호·지표·지도 제안을 다시 계산하지 않고 AI 또는 GOV-AI API도 호출하지 않는다. 따라서 실 API 구현 전에는 “현재 주차 재분석”과 “선택 주차 재분석” 모두 실제 기능을 정확히 표현하지 못한다.

자동화 검증이 다루는 범위

  • 수강생 본문에서 확신도 미노출, 강사·운영 본문에서 확신도 노출
  • 수강생 상세에서 sentAt이 있는 발송본만 표시
  • 강사 임시저장본의 운영 비공개와 저장 완료 후 운영 알림
  • 운영의 피드백 수정·임시저장·저장, 재분석 버튼의 mock 시각 갱신, 발송 대기본 일괄 발송
  • 일괄 발송 전 수강생 비공개, 발송 후 공개본 반영

현재 상태: 실제 BE 진단 API는 수강생 목록·상세 조회와 운영 수집까지 3개다. 지도자용 조회·임시저장·저장·재분석·일괄 발송 API와 알림 fan-out은 구현 대기이며, 실서버 전환 시 해당 FE 요청은 404가 날 수 있다.

7. BE 전달안: 현재 API와 예정 계약

아래 계약은 2026-09-09 기준이다. 먼저 실제 BE에 존재하는 3개 API를 고정하고, 이어서 FE가 로컬 mock으로 시연 중인 지도자용 계약을 분리했다.

실제 BE에 존재하는 진단 API

메서드·경로현재 기능주의점
GET /student/course/diagnosis/my-reports로그인한 수강생의 완료 주차 요약 목록주차 오름차순
GET /student/course/diagnosis/my-reports/{week}선택 주차 상세와 직전 저장 주차 비교값현재 BE 응답에는 instructorFeedback이 없음

운영·강사 조회, 재분석, 피드백 임시저장·저장·일괄 발송 API는 아직 BE에 없다. VITE_REAL_DIAGNOSIS=true로 mock을 끄면 이 요청들은 현재 404가 날 가능성이 크다.

재분석 버튼의 현재 한계

  • 버튼은 운영 화면에만 있고, 대상은 달력상 현재 주차가 아니라 화면에서 선택한 수강생·주차다.
  • 로컬 mock은 analyzedAt만 클릭 시각으로 바꾼다. level, gradeRationale, riskFlags, metrics, recommendationsForInstructor는 바뀌지 않는다.
  • AI나 GOV-AI API를 호출하지 않는다. 따라서 현재 버튼명과 실제 동작은 일치하지 않는다.
  • 실 API는 재분석의 입력 원천, 동기·비동기 처리 방식, 결과 교체 범위, 중복 요청 정책을 먼저 확정해야 한다. 성공 시에만 진단 결과와 analyzedAt을 함께 갱신해야 한다.

피드백 상태와 공개 경계

초기 편집값 = 현재 역할 temporaryDraft.content
          → savedFeedback.content
          → suggestedFeedbackDraft
          → ""

NONE → TEMP_SAVED → READY_TO_SEND → SENT
       역할 전용       저장 완료본       수강생 공개본
  • 강사와 운영의 temporaryDraft는 역할별로 격리한다. 임시저장은 수강생에게 전달되지 않는다.
  • savedFeedback은 강사·운영이 공유하는 저장 완료본이다. 강사 저장 시 managerNotifiedAt을 기록한다.
  • 운영 일괄 발송은 readyCount > 0일 때만 활성화하며, 아직 발송되지 않은 저장 완료본만 publishedFeedback으로 만든다.
  • 이미 발송한 뒤 새 저장 완료본이 생기면 READY_TO_SEND로 돌아가지만, 기존 publishedFeedback은 다음 발송까지 수강생에게 유지한다.
  • 수강생 상세에는 발송된 content, authorName, updatedAt, sentAt만 내려준다. 지도자용 초안·저장 상태·알림 정보는 포함하지 않는다.

서버 권한·검증 요구

  • 운영은 운영 범위, 강사는 JWT 기준 담당 기수만 조회·저장할 수 있어야 한다.
  • cohortId·studentUuid·week 소속을 서버에서 재검증한다.
  • 피드백 content는 trim 후 1~1000자이며, 저장 완료 시 해당 역할의 임시저장본을 비운다.
  • 일괄 발송 대상은 요청 body의 학생 목록이 아니라 해당 기수·주차의 최신 발송 대기본 전체를 서버가 조회한다.
  • 학생별 공개본과 알림 레코드를 생성하되 같은 피드백 버전의 재요청으로 중복 알림을 만들지 않는다.

현재 mock 전용 생성 규칙

  • riskFlags: 미접속 5일 이상, 또는 단계 정체 7일 이상일 때 생성한다. 공식 운영 정책이 아니라 로컬 샘플 기준이다.
  • recommendationsForInstructor: 미접속 5일 이상이면 안부 확인·재접속 유도, 단계 정체 5일 이상이면서 미완주면 1:1 원인 확인을 제안한다.
  • 등급별 지도 제안: 입문·초급은 반복 에러 기초 복습, 중급은 반복 에러 미니 과제·심화 질문, 해결사는 설계·오픈소스 등 심화 과제를 제안한다.
  • suggestedFeedbackDraft와 AI 피드백 원문은 실시간 AI 호출 결과가 아니다. 20주차 일부는 고정 샘플이고 다른 주차는 등급·에러·미접속 값으로 만든 템플릿이다.
  • staff 상세 mock의 dataFreshness는 현재 analyzedAt과 같은 값이고 missingMetrics는 빈 배열이다. 실데이터 의미와 동일하다고 보면 안 된다.
실명·식별자는 비식별 예시만 사용한다. 2026-09-09 현재 BE에 존재하는 수강생 조회·수집 API와 FE가 요청하는 지도자 관리 계약을 구분해 기록했다.
