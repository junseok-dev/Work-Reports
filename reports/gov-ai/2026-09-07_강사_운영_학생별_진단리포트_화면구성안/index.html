1. 같은 위치, 같은 진단 화면

학생 선택 → 주차 선택 → 상태와 근거 → 지도 제안 순서로 확인한다. 기존 수강생 평가 점수와 AI 진단은 서로 대체하지 않는다.

수치를 먼저 나열하기보다 무엇을 확인해야 하는 학생인가 → 왜 그렇게 판단했는가 → 무엇을 지도할 것인가에 맞춰 배치한다.

4. 7종 mock과 5개 API는 같은 재료의 다른 구분

이 보고서에서는 혼선을 피하려고 API 번호보다 경로를 기준으로 쓴다. 9월 3일의 5개 API 목록과 이후 수강생 전용 3개 API 문서는 번호가 서로 다르다.

보관 샘플원천이 화면에서의 사용
weekly cached / past W34 / refresh (3종)GET /reports/weekly/{uuid}한 학생의 시점별 관측·판정 근거·위험 신호·지도 제안 검토. cached와 refresh는 같은 주차의 다른 스냅샷으로 별도 취급
certificateGET /certificate/{uuid}승인 메타·요약을 참고하되 주차 근거와 혼합하지 않음. 예전 수치가 서술에 남아 있는 샘플도 있어 일치 검증 필요
diagnosePOST /analysis/diagnose/{uuid}즉시 실행 결과의 필드 형태만 검토. 주차 식별 보장 없이 최신 시각만으로 주간 판정을 덮어쓰지 않음
historyGET /reports/history/{uuid}기본 화면의 기준. 보관된 4주 이력으로 학생별 주차 본문 구성
approvePOST /feedback/approve행위 결과 샘플. 리포트 내용을 제공하는 조회 API가 아님. 실제 승인·전달 버튼은 별도 계약 확정 후 구현

선택: 7종을 근거 범위로 삼되 기본 시안은 history의 일관된 스냅샷을 사용한다. 상세 화면에 5개 API를 매번 모두 호출하지 않는다. weekly의 없는 주차 생성·refresh와 diagnose·approve는 읽기 조회가 아니므로 이 보고서에서 실행하지 않았다.

보관 샘플의 학생은 1명이다. 7종을 7명으로 늘리거나 실제처럼 보이는 이름·성적을 생성하지 않았다. 여러 학생 목록은 담당 기수 명단과 학생별 응답을 확보한 뒤 채운다.

주차는 원천의 ISO 주차로 표시했다. 화면용 기수 주차는 검증된 기수 시작일로 변환해야 하며, 이 시안에서 임의 환산하지 않는다. W36은 샘플 수집 시점에 진행 중이던 주차다. 기본은 당시 완료된 W35이고, W36은 비교용 보관 샘플임을 표시한다.

5. 공용 화면과 BE 연결 경계

항목제안현재 확인된 한계
공용 화면역할별 허브에서 같은 학생 목록·상세 컴포넌트를 사용. 기수·학생·주차를 선택 상태로 유지강사의 추천서 영역은 기존 평가 탭에 유지. 공용 컴포넌트 위치는 저장소 가이드에 맞춰 확정
최초 조회허용된 기수의 학생 목록과 진단 제공 여부를 조회5개 원천 API는 학생 단위이며 기수 명단 API가 아니다. 기존 LMS 명단 연결과 식별자 매핑 필요
학생 선택그 학생의 완료 주차 요약 목록 조회현재 BE /student/course/diagnosis/my-reports는 토큰 본인 조회. 학생 ID를 붙여 강사 조회로 재사용할 수 없음
주차 선택선택 학생·주차의 상세 1개 + 전주 비교값 조회. 캐시 키에 기수·학생·주차 포함현행 개인 BE DTO는 grade_rationale·risk_flags·지도 제안·초안을 제공하지 않음. 원천에 있는 것과 현재 LMS API에 있는 것은 다름
주차 변경선택 본문만 교체. 없는 주차는 건너뛰고 전주 비교는 정확한 직전 주차만원천 history를 BE에서 읽을 때는 전체 이력을 받을 수 있어도 FE 본문은 한 주차만 표시
승인·전달초안 열람부터 시작. 저장·승인·전달은 후속 단위approve 샘플의 SUCCESS만으로 학생·주차·본문 버전 일치를 증명하지 못함. 운영의 승인 권한도 미확정

반드시 구분할 화면 상태

  • 학생 목록 로딩 / 검색 결과 없음 / 기수에 학생 없음 / 권한 없음.
  • 선택 학생의 리포트 없음 / 해당 주차 없음 / 호출 실패 + 다시 시도.
  • 일부 지표 누락: 해당 항목만 —. 0과 null을 구분하고 진단 본문 전체를 숨기지 않는다.
  • 지도 제안·피드백 없음: 원천 미제공이라고 표시. 빈 내용을 AI로 새로 생성하지 않는다.
  • 시각은 원천 UTC를 확인해 KST로 표시하고, 오래된 관측과 현재 관측을 같은 주차 안에서 섞지 않는다.

실 API 연결 전 필요한 계약은 담당 기수 학생 목록 → 학생별 주차 목록 → 학생·주차 상세의 세 경계다. 새 URL과 권한 정책은 BE와 협의할 제안이며, 존재하는 API라고 표기하지 않는다.

6. 이 초안에서 함께 정할 것

  1. 위치: 수강생 평가 내부 2탭과 운영의 기존 독립 진단 탭 이동에 동의하는가.
  2. 순서: 학생 선택 → 판정·신호 → 근거 → 정량 기록 → 주차 흐름 → 지도 제안 → 초안이 실제 검토 순서에 맞는가.
  3. 범위: 1차는 학생별 진단 열람으로 한정하고 승인·전달은 계약 확정 뒤 분리할 것인가.
  4. 보여줄 원천: 단계 정의·출결·과제 관련 미검증 주장이 포함된 AI 원문을 검토 전용으로 접어 둘지 결정한다.

다음 구현 단위: 공용 진단 열람 화면과 강사·운영 진입 연결. 이후 담당 학생 조회 계약·상태 처리, 마지막으로 피드백 승인·전달을 각각 검토한다. 실제 FE·Figma 구조 변경은 이 시안을 확인한 뒤 진행한다.
