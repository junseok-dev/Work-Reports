7. BE 담당자 전달용 최신 API 계약안

아래 지도자용 API는 2026-09-09 현재 FE와 로컬 mock에 반영한 구현 요청안이다. 수강생 본인용 조회 API와 분리하며, admin과 instructor의 권한 범위는 서버가 판정한다.

역할·메서드제안 경로요청/응답
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students수강생 배열: studentUuid, name, reportCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports주차 배열: week, baseDate, endDate, feedbackStatus, readyCount, sentCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}진단 상세 + suggestedFeedbackDraft + instructorFeedback 상태 객체
운영/강사 PUT/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/feedback/draft{"content":"현재 역할의 임시저장 값"}
운영/강사 POST/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/feedback/submit{"content":"저장 완료 값"}. 공유 저장본·발송 대기 갱신
운영 POST/admin/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/reanalyzebody 없음. 해당 학생·주차 재분석
운영 POST/admin/cohorts/{cohortId}/diagnosis/reports/{week}/instructor-feedbacks/sendbody 없음 → requestedCount, sentCount, skippedStudentUuids

피드백 상태

NONE → TEMP_SAVED → READY_TO_SEND → SENT
         역할 전용       공유 저장본       수강생 공개본

편집 초기값 = temporaryDraft?.content
          ?? savedFeedback?.content
          ?? suggestedFeedbackDraft
          ?? ""

발송 완료 뒤 강사나 운영이 새 저장 완료본을 만들면 hasUnsentChanges=true가 되어 다시 READY_TO_SEND 상태가 된다. 기존 publishedFeedback은 다음 발송 전까지 수강생에게 계속 표시한다.

수강생 본인 상세의 피드백 경계

GET /student/course/diagnosis/my-reports/{week}의 instructorFeedback은 content, authorName, updatedAt, sentAt만 가진다. sentAt이 없거나 객체가 없으면 FE는 피드백 블록을 표시하지 않는다. 지도자용 temporaryDraft·savedFeedback·알림 상태는 절대 포함하지 않는다.

권한·저장·알림 요구

  • admin/manager는 허용된 운영 범위, instructor는 JWT의 담당 기수만 조회·저장한다.
  • cohortId·studentUuid·week 소속을 서버에서 재검증하고 이름으로 저장하지 않는다.
  • content는 trim 후 1~1000자다. 임시저장본은 역할별로 분리하고, 저장 완료 시 해당 역할의 임시저장본을 비운다.
  • 저장 완료본에는 authorRole을 남긴다. 강사 저장이면 managerNotifiedAt을 갱신하고, 운영 저장이면 새 강사 알림으로 취급하지 않는다.
  • 재분석은 운영만 가능하며 성공한 학생·주차 상세의 analyzedAt과 진단 결과를 갱신한다.
  • 운영 일괄 POST는 body의 학생 목록을 신뢰하지 않고 해당 기수·주차의 최신 발송 대기본 전체를 서버가 조회한다.
  • 수강생마다 별도 공개본과 알림 레코드를 생성하며, 같은 피드백 버전 재요청은 중복 알림을 만들지 않는다.
  • 발송 대기본이 없거나 이미 최신본이 발송된 학생은 skippedStudentUuids로 반환한다.

현행 BE와의 차이

수강생 본인용 주차 목록·상세 계약은 FE에 연결되어 있다. 반면 지도자용 학생 목록·학생별 주차·상세와 역할별 임시저장·저장, 운영 재분석·일괄 발송은 별도 구현이 필요하다. 로컬 MSW 동작은 계약 시연용이며 BE 구현 완료의 증거가 아니다.
