7. BE 담당자 전달용 API 계약안

아래 API는 2026-09-08 현재 존재하지 않는 구현 요청안이다. FE는 이 경로와 camelCase 응답을 기준으로 연결했다.

역할·메서드제안 경로요청/응답
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students수강생 배열: studentUuid, name, reportCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports주차 배열: week, baseDate, endDate, feedbackStatus, draftCount, sentCount
운영/강사 GET/{role}/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}진단 상세 + suggestedFeedbackDraft + instructorFeedback
강사 PUT/instructor/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/instructor-feedback{"content":"강사가 수정한 값"}. 저장 후 DRAFT
운영 POST/admin/cohorts/{cohortId}/diagnosis/reports/{week}/instructor-feedbacks/sendbody 없음 → requestedCount, sentCount, skippedStudentUuids

강사 저장 request 매핑

  • cohortId: 현재 강사 허브의 경로 파라미터.
  • studentUuid: 첫 GET에서 고른 수강생 드롭다운 value. 이름을 보내지 않는다.
  • week: 두 번째 GET이 반환한 기수 주차 정수. ISO 주차 문자열을 보내지 않는다.
  • content: textarea 현재 문자열. 초기값은 instructorFeedback.content ?? suggestedFeedbackDraft ?? ""다.
PUT /instructor/cohorts/{cohortId}/diagnosis/students/{studentUuid}/reports/{week}/instructor-feedback
Content-Type: application/json

{
  "content": "강사가 검토 후 수정한 피드백"
}

권한·저장·알림 요구

  • admin/manager는 허용된 운영 범위, instructor는 JWT의 담당 기수만 조회·저장한다.
  • cohortId·studentUuid·week 소속을 서버에서 재검증하고 이름으로 저장하지 않는다.
  • content는 trim 후 1~1000자. 강사가 수정 저장하면 같은 학생·주차 저장본을 갱신하고 DRAFT로 되돌린다.
  • admin 상세 GET도 같은 instructorFeedback을 반환한다. 운영 전용 피드백 필드는 필요 없다.
  • 운영 일괄 POST는 body의 학생 목록을 신뢰하지 않고 해당 기수·주차의 최신 DRAFT 저장본 전체를 서버가 조회한다.
  • 수강생마다 별도 알림 레코드와 진단리포트 링크를 생성하며, 같은 피드백 버전 재요청은 중복 알림을 만들지 않는다.
  • 이미 SENT이거나 저장본이 없는 학생은 skippedStudentUuids로 반환한다.

현행 BE와의 차이

현행은 수강생 본인용 GET 2개와 운영 수집용 POST만 있다. 본인용 GET은 토큰 userId만 사용하므로 지도자 조회에 재사용하면 안 된다. 현행 WeekDetail에는 riskFlags, recommendationsForInstructor, suggestedFeedbackDraft, instructorFeedback, analyzedAt가 없어 확장이 필요하다.
