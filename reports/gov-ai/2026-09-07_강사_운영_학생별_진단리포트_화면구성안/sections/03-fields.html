3. 화면 필드와 요청 매핑

FE 조회 순서는 기수 수강생 목록 → 선택 학생의 주차 목록 → 학생·주차 상세다. 원천 GOV-AI 필드는 BE가 camelCase 화면 계약으로 변환한다.

화면BE 응답 필드원천/저장 필드처리 원칙
수강생 드롭다운studentUuid, name, reportCountLMS 기수 명단 + 진단리포트 매핑선택 value는 studentUuid. 이름은 표시 전용
주차 사이드 탭week, baseDate, endDate, feedbackStatus, draftCount, sentCount선택 학생의 완료 리포트 + 주차별 발송 집계week는 1부터 시작하는 기수 주차. 최신 완료 주차를 기본 선택하고 없는 주차는 만들지 않음
판정·근거level, confidence, gradeRationale, weakPatterns, riskFlagsgrade, confidence, grade_rationale, weak_patterns, risk_flags원천 AI 의견임을 표시하고 별도 위험 점수를 만들지 않음
활동 지표metrics.activeDays, totalRuns, totalErrors, errorPerRun, hintRequestsCount, hintPerActiveDay, avgRetryGapMin, maxRetryGapMin, topErrorTypesmetrics의 snake_case 필드0은 실제 0, null은 원천 미제공. missingMetrics와 함께 항목별로 — 표시
강사 편집 초기값suggestedFeedbackDraftsuggested_feedback_draft강사 저장본이 없을 때 textarea value. suggested가 정식 철자
강사 저장본instructorFeedback.content, authorName, updatedAt, sentAtLMS 강사 피드백저장본이 있으면 제안 초안보다 우선. 운영은 읽기 전용
관리 상태feedbackStatus: NONE / DRAFT / SENTLMS 저장·발송 상태DRAFT는 강사 저장 완료, SENT는 운영 일괄 발송 완료

운영 피드백 필드는 두지 않는다. draftCount와 sentCount는 선택 학생 개인 수가 아니라 해당 기수·주차의 운영 발송 집계이며, 운영 일괄 발송 버튼 상태와 결과 갱신에 쓴다.
