7. 확정 항목을 넣으려면 무엇이 더 필요한가

확정 보고서가 정한 여섯 가지를 화면에 올린다고 할 때, 지금 fixture로 되는 것과 더 받아야 하는 것을 가른다. 기준은 하나다 — 명세서의 다섯 API를 실제로 호출해 받은 값만 쓴다.

확정 항목지금 되나이유
에러당 힌트
문제 해결 방식 · 막힌 영역		된다api4-history.json 한 행에서 전부 계산된다. hint_requests_count·total_errors·avg_retry_gap_min·top_error_types가 다 들어 있다
등급 변화 이력 · 에러율 추세
단계 증가 속도		된다W33~W36 4주가 이미 배열로 들어 있다. 주차 간 차분만 하면 된다
(참고) 진도율의 분모부분total_steps가 api2-certificate.json에 있다. 두 파일을 함께 읽으면 상수 10을 없앨 수 있다
기수·반 평균 대비 비교안 된다지금 fixture는 학생 한 명이다. 분포를 계산할 상대가 없다
확정 여섯 가지는 추가 수집이 전혀 필요 없다. 파일도 그대로, 호출도 그대로다. adapter.ts와 derive.ts에 계산과 문장 생성을 더하는 일만 남는다.

분포를 하려면 — 표본이 얇다

다섯 API 중 여러 학생의 주차 지표를 주는 것은 /reports/history뿐인데 학생마다 따로 호출해야 한다.

관측내용
표본15명을 확인했을 때 리포트가 있는 학생이 6명이었고 대부분 1주치뿐이었다. 4주가 온 것은 데모 시드 계정 하나였다
호출 비용기수 전체를 보려면 학생 수만큼 호출해야 한다. 한 번에 여러 학생을 주는 엔드포인트가 다섯 API 안에 없다
판단표본이 쌓일 때까지 분포·백분위는 화면에 올리지 않는다. 없는 학생을 지어내면 화면은 그럴듯해지지만 실연동에서 전혀 다른 그림이 나온다
