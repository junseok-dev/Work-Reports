5. 피드백 임시저장·저장·발송

저장 API 요청값

{ "content": "현재 편집창에 있는 전체 피드백 본문" }
content는 항상 전체값입니다. AI 초안 그대로 저장해도 보내고, 강사나 운영이 수정했다면 수정된 전체 본문을 보냅니다. 변경된 부분만 보내지 않습니다.

초안과 수정본 구분

  • BE는 API 4의 feedback_draft를 suggestedFeedbackDraft 원본으로 저장합니다.
  • 저장 요청의 content와 원본 초안을 비교해 isModifiedFromSuggestion을 계산합니다.
  • 초안과 같아도 최초 저장은 정상 저장하고 발송 대기로 만듭니다.
  • 직전 저장본과 같은 값을 다시 저장하면 성공 처리하되 중복 버전·중복 알림은 만들지 않습니다.

DB에 필요한 최소 필드

구분필드
대상educationId, cohortId, studentUuid, week
원본·본문suggestedFeedbackDraft, content, isModifiedFromSuggestion
작성자authorUuid, authorName, authorRole
상태·시각status, updatedAt, managerNotifiedAt, sentAt
외부 승인 선택govAiFeedbackLogId

과정명·기수명·학생명·작성자명은 요청 body를 신뢰하지 않고 cohortId, studentUuid, JWT로 BE가 조회합니다.

API 5를 연결하는 경우

운영 일괄 발송 시 학생별로 아래 값을 API 5에 보낼 수 있습니다. 단, API 5에는 과정·기수·주차와 임시저장 상태가 없으므로 LMS DB가 반드시 정본이어야 합니다.

POST /feedback/approve { "studentUuid": "student-uuid", "approved_by": "JWT에서 조회한 운영자명", "feedback_text": "LMS 저장 완료본의 content", "status": "APPROVED" }

일괄 발송 응답: educationId, educationTitle, cohortId, cohortLabel, week, requestedCount, sentCount, sentStudentUuids[], skippedStudentUuids[]를 반환하면 어느 과정·몇 기·어느 학생에게 발송했는지 확인할 수 있습니다.

공개 보고서이므로 실명·실제 학생 식별자·인증정보는 포함하지 않습니다. 경로와 필드명은 2026-09-09 LMS-FE 계약과 LMS-BE 구현을 대조한 기준입니다.
