GOV-AI 주간 진단 리포트 API 응답 검증

명세서의 5개 API를 직접 호출해 응답 필드를 확인하고, 출결·과제·퀴즈 데이터가 어디에서 오고 어디에서 오지 않는지를 호출 근거와 함께 정리한다.

작성일 2026-09-03API 실호출 검증GOV-AI DataLake v1.0.0

1. 검증 개요

GOV-AI DataLake 명세서(REPORT-API-CALL.md v1.3)가 정의한 5개 API를 2026-09-03에 직접 호출해 실제 응답 필드를 확인했다. 주간 진단 리포트 화면을 구성할 때 어떤 값을 쓸 수 있고 어떤 값이 없는지를 호출 근거와 함께 정리한다.

검증 대상: https://datalake.isitsoft.kr/api/v1 · API v1.0.0 · 인증 헤더 X-DE-API-KEY. 검증 수강생은 명세서 예시와 동일한 100030029410(정승, 29기 A반)이다.

호출 환경

이 문서의 모든 명령은 아래 환경변수를 전제한다. 키는 저장소에 두지 않는다.

export DE_API_KEY="<명세서 1.1의 X-DE-API-KEY>"
export B="https://datalake.isitsoft.kr/api/v1"
export U="100030029410"
export PYTHONIOENCODING=utf-8
Windows 주의: Git Bash·PowerShell 모두 curl.exe에 명령행 인자를 넘길 때 한글을 시스템 코드페이지(CP949)로 변환한다. 한글이 든 요청 본문을 -d로 인라인 전달하면 서버가 UTF-8로 디코딩하지 못해 400 There was an error parsing the body가 난다. 본문은 파일로 저장해 --data-binary @file로 보내야 한다. macOS·Linux에서는 명세서 예시가 그대로 동작한다.

응답을 읽을 때

curl -sS "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY"   | python -m json.tool --no-ensure-ascii

PYTHONIOENCODING=utf-8과 --no-ensure-ascii가 둘 다 있어야 한글이 보인다. 앞이 없으면 콘솔 코드페이지에서 깨지고, 뒤가 없으면 정승 형태로 이스케이프된다.

질문결론
주간 리포트에 출결이 오는가온다. API 1·2·4에 attendance_rate 필드가 있다. 다만 전 학생·전 주차가 100.0 상수다

왜 있었다 없었다 했는가세 가지 층위(문서 안/밖 · 필드/값 · 주차별/누적)가 섞여 있어서다. 4장에서 다룬다

2. API 1~5 호출과 응답

명세서 §2의 다섯 엔드포인트를 순서대로 호출한 결과다. 각 호출의 실제 명령, 응답 최상위 구조, 출결·과제·퀴즈 필드의 유무를 함께 기록한다.

API 1. 주간 AI 학습 맞춤 진단 리포트

curl -X GET "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY"

최상위 10개 블록이 온다.

studentUuid · year_week · week_no · week_label · week_range · cached
metrics · diagnosis · weakness · risk

metrics는 24필드다. 이 목록이 진단 리포트가 쓸 수 있는 지표의 전부다.

studentUuid  userId  name  cohortId  cohort  group  language
steps_completed  current_step  stalled_days_on_current_step  days_since_last_activity
active_days_count  total_runs  total_errors  error_per_run
hint_requests_count  hint_per_active_day  avg_retry_gap_min  max_retry_gap_min
top_error_types  assignments_completed  attendance_rate  data_freshness  missing_fields
항목실측값확인 내용
출결attendance_rate = 100.0필드 존재. 값은 상수(3장 참조)
과제assignments_completed = 0
missing_fields = ["assignments"]		필드 존재. 서버가 같은 응답에서 미수집을 선언
퀴즈—필드 없음. 24필드 전수에 quiz를 포함하는 키가 하나도 없다

API 2. LMS 연동용 역량 증명서

curl -X GET "$B/certificate/$U" -H "X-DE-API-KEY: $DE_API_KEY"
version · issue_timestamp · student · summary · technical_proof
project_and_portfolio · ai_analysis_narrative · human_in_the_loop

출결·과제는 project_and_portfolio 안에 있고, 필드명이 API 1과 다르다.

"project_and_portfolio": {
  "completed_assignments": 0,      // API 1은 assignments_completed
  "attendance_rate": 100.0,
  "collaboration_score": 85.0
}

퀴즈 필드는 없다. summary.total_steps = 10은 이 API에만 있어, 진행률을 10/10으로 표시하려면 여기서 가져오거나 상수로 두어야 한다.

API 3. 온디맨드 수준 진단

curl -X POST "$B/analysis/diagnose/$U" -H "X-DE-API-KEY: $DE_API_KEY"

최상위 10필드가 평탄하게 온다. API 1의 diagnosis 블록과 같은 구성이다.

studentUuid · grade · confidence · grade_rationale · weak_patterns · risk_flags
recommendations_for_instructor · suggested_feedback_draft · analyzed_at · model_meta
지표가 아예 없다. total_runs·error_per_run 같은 정량 값도, 출결·과제·퀴즈도 오지 않는다. 진단 텍스트만 반환하는 엔드포인트다.

API 4. 주차별 리포트 이력

curl -X GET "$B/reports/history/$U?limit=5" -H "X-DE-API-KEY: $DE_API_KEY"

배열로 오며 항목당 20필드다. API 1과 필드명이 다르다.

API 1 (weekly)API 4 (history)
studentUuidstudent_uuid
diagnosis.recommendations_for_instructorrecommendations
diagnosis.suggested_feedback_draftfeedback_draft
risk.statusrisk_status
diagnosis.model_meta.provider · .modelllm_provider · llm_model
4개 블록 중첩전부 평탄화 + metrics_snapshot · markdown_content

주차별 metrics_snapshot을 열면 주차마다 필드 수가 다르다.

2026-W33  필드  7개  attendance_rate=100.0  assignments_completed=(필드 없음)
2026-W34  필드  7개  attendance_rate=100.0  assignments_completed=(필드 없음)
2026-W35  필드 24개  attendance_rate=100.0  assignments_completed=0
2026-W36  필드 24개  attendance_rate=100.0  assignments_completed=0

과거 두 주차는 steps_completed · current_step · total_runs · total_errors · error_per_run · active_days_count · attendance_rate 7개로 축약된다. 힌트·재시도·정체·에러 유형이 없다. 출결만 모든 주차에 살아 있다.

API 5. 강사 피드백 승인

cat > payload.json <<'EOF'
{
  "studentUuid": "100030029410",
  "approved_by": "[TEST] 필드 확인",
  "feedback_text": "[TEST] API 5 응답 필드 확인용",
  "status": "APPROVED"
}
EOF

curl -X POST "$B/feedback/approve" -H "X-DE-API-KEY: $DE_API_KEY"   -H "Content-Type: application/json" --data-binary @payload.json
{"status": "SUCCESS", "log_id": "fb_20260903103059_100030029410", "approved_by": "[TEST] 필드 확인"}

응답은 3필드뿐이다. 출결·과제·퀴즈와 무관하다. 승인 로그가 누적 생성되고 삭제 API가 없으므로, 검증 호출에는 [TEST] 표기를 붙여 나중에 골라낼 수 있게 했다.

log_id의 시각 103059는 KST다. 같은 순간 다른 응답의 analyzed_at·data_freshness·issue_timestamp는 UTC로 온다. 한 서비스 안에서 타임존이 섞여 있다.

진단 리포트가 실제로 쓰는 지표

위 셋을 제외하면 주간 진단 리포트의 원천은 PlayLang 실습 로그다.

진도    steps_completed · current_step · (total_steps는 C에만)
활동    active_days_count · stalled_days_on_current_step · days_since_last_activity
실행    total_runs · total_errors · error_per_run
힌트    hint_requests_count · hint_per_active_day
재시도  avg_retry_gap_min · max_retry_gap_min
에러    top_error_types[{type, count}]   ← 상위 3개만
top_error_types는 상위 3개만 온다. 실측에서 세 건의 합이 total_errors의 62.6%였다. 나머지 37.4%는 어느 응답에도 나타나지 않으며 "기타" 항목도 없다. 화면에 막대그래프를 그리면 합이 전체와 맞지 않는다.

4. 출결·과제·퀴즈가 "있다/없다"로 갈린 이유

검토 과정에서 이 셋을 두고 "온다"와 "없다"가 반복해서 뒤집혔다. 세 가지 층위가 섞여 있었기 때문이다. 각각을 분리하면 모순이 사라진다.

층위 1 — 문서 안의 API인가, 문서 밖인가

명세서 REPORT-API-CALL.md는 5개 API만 다룬다. 그런데 실제 서버의 /openapi.json에는 24개 엔드포인트가 있고, 그중 /sync/students에 출결·과제·퀴즈 상세가 들어 있다.

말한 내용가리킨 곳참·거짓
"퀴즈 데이터가 왔다"/sync/students (문서 밖)참
"퀴즈 필드가 없다"명세서 5개 API참

둘 다 사실이지만 가리키는 엔드포인트가 달랐다. 어느 쪽을 말하는지 붙이지 않아 모순처럼 들렸다. 이 문서에서 /sync/students를 S로 따로 표기하고 fixture 파일명에 ext- 접두사를 붙인 이유가 이것이다.

층위 2 — 필드가 있는가, 값이 쓸모 있는가

출결·과제는 필드가 실제로 온다. 그래서 "온다"는 말이 맞다. 그러나 값이 상수라 화면에 쓸 수 없다. "쓸 수 있나"로 물으면 답이 뒤집힌다.

필드 존재 여부   attendance_rate  ✅ 있음      assignments_completed  ✅ 있음
값의 유효성      100.0 상수       ❌ 못 씀     0 + missing_fields     ❌ 못 씀

게다가 둘은 못 쓰는 이유가 서로 다르다.

항목missing_fields해석
과제["assignments"]에 포함서버가 "이 데이터를 못 받았다"고 스스로 알린다. 값 0은 기본값이다. 정직한 처리다
출결미포함서버는 "받았다"고 본다. 그런데 값이 전원 100.0이다. 결측이 아니라 틀린 값이라 더 위험하다

층위 3 — 주차별인가, 누적인가

S의 상세값은 실제 데이터다. 문제는 last_synced_at 시점의 누적 현재값이라는 점이다. 주차를 바꿔가며 봐도 같은 값이 나온다.

11주차(W33)를 봐도  → attendance {present 101, late 5, absent 4}
14주차(W36)를 봐도  → attendance {present 101, late 5, absent 4}   동일

그래서 "지난주 대비 출석률" 같은 문장을 만들 수 없다. 비교할 이전 주 값이 존재하지 않는다.

정리하면

항목5개 API 필드값S의 상세주간 리포트 사용
출결있음 (W·C·H)100.0 상수있음 (누적)값 보강 시 가능
과제있음 (W·C·H)0 + 미수집 선언있음 (누적)불가
퀴즈없음—있음 (누적)불가

이 값들의 원천은 LMS다

S의 출결·과제·퀴즈는 GOV-AI가 수집한 것이 아니라 LMS가 넘긴 데이터다. LMS-DOCS/10_데이터/외부_AI_코칭_API.md가 정의한 data-ingest-api가 원천이며, 양쪽이 같은 X-DE-API-KEY 헤더를 쓴다.

  GET /ingest/v1/courses?include=activities
