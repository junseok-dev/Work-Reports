4. 주간 진단 리포트가 쓰는 데이터

진단 리포트는 수강생 한 명의 한 주를 다룬다. 화면 항목마다 어떤 필드를 읽고 그 값이 어떻게 문장·숫자가 되는지를 실측과 함께 정리한다.

4.1 화면은 호출 하나만 쓴다

3장의 다섯 호출 중 화면이 부르는 것은 API 4 하나다. 한 번에 여러 주차가 배열로 오므로 주차 전환에 추가 호출이 필요 없다.

curl -X GET "$B/reports/history/$U?limit=5" -H "X-DE-API-KEY: $DE_API_KEY"

데모 계정 황수빈(100051503818)은 4주치가 온다. 주차마다 값이 실제로 달라진다.

4.3 서술 네 개 중 셋은 우리가 만든다

API 4가 학생별로 주는 서술은 weak_patterns 하나뿐이다. 나머지 세 섹션은 대응하는 필드가 없어 지표에서 만든다. 원칙은 근거가 있는 문장만 만든다이며, 근거 없는 격려 문구는 넣지 않는다.

항목성격만드는 방식과 기준
보완하면 좋은 점원천weak_patterns를 그대로 싣는다.
지난주 대비 변화계산앞 주차 행과 steps_completed·error_per_run·total_runs를 비교한다. 값이 같으면 그 문장은 만들지 않는다. 첫 주차는 비교 대상이 없어 출발점만 적는다.
잘하고 있는 점생성네 조건을 각각 검사한다 — 단계 완료, 에러율 0.3 미만, 활동일 5일 이상, 정체·미접속 0.
이번 주 학습 제안생성임계값에 걸린 항목만 제안한다 — 미접속 3일↑, 정체 3일↑, 힌트 20회/일↑, 재시도 0.5분↓, 에러율 0.3↑.
임계값은 실측 분포에서 잡았다. 관측 범위가 힌트 4.5~50.9회/일, 에러율 0.10~0.45, 재시도 0.2~0.3분이었다. 이전에 쓰던 기준(힌트 2회/일)은 실제와 20배 차이가 나 그대로 두면 전원이 "힌트 과다"로 걸린다.

4.4 받지만 쓰지 않는 것

API 4가 주는 44필드 중 화면이 읽는 것은 25개다. 나머지를 쓰지 않는 이유는 넷으로 나뉜다.

분류필드쓰지 않는 이유
신원student_uuid · cohort_label · metrics_snapshot의 이름·기수·반·언어·UUID 7필드로그인한 본인 화면이라 다시 받을 이유가 없다
집계assignments_completed · attendance_rate · missing_fields값이 고정이거나 미수집이다 — 5장
운영id · week_label · risk_score · created_at · data_freshness레코드 관리용이다
강사용recommendations강사 권장 조치라 수강생 화면에 노출하지 않는다
top_error_types는 상위 3개만 온다. 실측에서 세 건의 합이 total_errors의 62.6%였고, 나머지 37.4%는 어느 응답에도 나타나지 않으며 "기타" 항목도 없다. 막대그래프를 그리면 합이 전체와 맞지 않는다.
총 단계 수가 응답에 없다. total_steps는 API 2에만 있고 화면이 쓰는 API 4에는 없어, 지금은 코드에 상수 10을 두고 있다. API 2를 함께 부르거나 API 4에 필드가 추가돼야 없앨 수 있다.
