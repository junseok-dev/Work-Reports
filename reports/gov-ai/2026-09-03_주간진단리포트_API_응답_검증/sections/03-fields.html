3. 응답 필드 사전

2장의 호출이 돌려준 필드를 전부 편다. 각 필드가 무엇인지, 어떤 값이 왔는지, 진단 리포트가 쓰는지를 함께 적는다. 표의 출처는 아래 호출을 가리킨다.

출처호출무엇을 부른 것인가
API 1GET /reports/weekly/$U?format=json주간 AI 학습 맞춤 진단 리포트
API 2GET /certificate/$ULMS 연동용 역량 증명서
API 3POST /analysis/diagnose/$U온디맨드 수준 진단
API 4GET /reports/history/$U?limit=5주차별 리포트 이력
API 5POST /feedback/approve강사 피드백 승인
/sync/studentsGET /sync/students?limit=200학생 마스터 동기화 — 명세서 밖
쓰임 열의 ●는 현재 수강생 진단 리포트 화면이 실제로 읽는 필드다. 화면은 API 4(주차별 리포트 이력) 하나만 호출하므로 API 1·2·3·5는 전부 ·가 된다. 같은 지표가 API 1에도 있지만 경로와 필드명이 달라 그대로 바꿔 끼울 수 없다. 어느 필드가 화면의 어느 항목이 되는지는 4장에서 다룬다.

같은 값이 세 곳에등급·확신도·근거·약점·피드백 초안은 API 1·3·4 모두에 있다. API 1의 diagnosis 블록은 API 3의 최상위와 키가 100% 일치한다. 어느 쪽을 원본으로 볼지 정해두지 않으면 값이 갈렸을 때 판단할 근거가 없다.
같은 뜻, 다른 이름studentUuid↔student_uuid, suggested_feedback_draft↔feedback_draft, recommendations_for_instructor↔recommendations, assignments_completed↔completed_assignments. 표기법(camel/snake)과 어순이 API마다 다르다.
같은 이름, 다른 모양model_meta가 API 1·2는 5키, API 3은 3키다. prompt_version은 API 3에만, cached·week_label은 API 1·2에만 있다.
확신도가 어긋난다같은 학생·같은 시점인데 API 1은 0.8, API 3은 0.85다. API 3은 POST로 호출할 때마다 새로 분석하므로 캐시본인 API 1과 값이 벌어진다.
총 단계 수는 API 2에만total_steps는 API 2의 summary에만 있다. 화면이 쓰는 API 4에는 없어 FE가 상수 10을 들고 있다.
고정값이 섞여 있다attendance_rate 100.0, collaboration_score 85.0, error_resolution_rate 0.95, human_in_the_loop.status APPROVED는 학생과 주차를 바꿔도 움직이지 않았다. 필드가 온다는 것과 값이 쓸 만하다는 것은 별개다.
