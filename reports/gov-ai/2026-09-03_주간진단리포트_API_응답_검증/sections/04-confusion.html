4. 출결·과제·퀴즈가 "있다/없다"로 갈린 이유

검토 과정에서 이 셋을 두고 "온다"와 "없다"가 반복해서 뒤집혔다. 세 가지 층위가 섞여 있었기 때문이다. 각각을 분리하면 모순이 사라진다.

층위 1 — 문서 안의 API인가, 문서 밖인가

명세서 REPORT-API-CALL.md는 5개 API만 다룬다. 그런데 실제 서버의 /openapi.json에는 24개 엔드포인트가 있고, 그중 /sync/students에 출결·과제·퀴즈 상세가 들어 있다.

말한 내용가리킨 곳참·거짓
"퀴즈 데이터가 왔다"/sync/students (문서 밖)참
"퀴즈 필드가 없다"명세서 5개 API참

둘 다 사실이지만 가리키는 엔드포인트가 달랐다. 어느 쪽을 말하는지 붙이지 않아 모순처럼 들렸다. 이 문서에서 표의 출처를 API 번호로 적고 /sync/students만 경로 그대로 표기하는 이유, fixture 파일명에 ext- 접두사를 붙인 이유가 이것이다.

층위 2 — 필드가 있는가, 값이 쓸모 있는가

출결·과제는 필드가 실제로 온다. 그래서 "온다"는 말이 맞다. 그러나 값이 상수라 화면에 쓸 수 없다. "쓸 수 있나"로 물으면 답이 뒤집힌다.

필드 존재 여부   attendance_rate  ✅ 있음      assignments_completed  ✅ 있음
값의 유효성      100.0 상수       ❌ 못 씀     0 + missing_fields     ❌ 못 씀

게다가 둘은 못 쓰는 이유가 서로 다르다.

항목missing_fields해석
과제["assignments"]에 포함서버가 "이 데이터를 못 받았다"고 스스로 알린다. 값 0은 기본값이다. 정직한 처리다
출결미포함서버는 "받았다"고 본다. 그런데 값이 전원 100.0이다. 결측이 아니라 틀린 값이라 더 위험하다

층위 3 — 주차별인가, 누적인가

/sync/students의 상세값은 실제 데이터다. 문제는 last_synced_at 시점의 누적 현재값이라는 점이다. 주차를 바꿔가며 봐도 같은 값이 나온다.

11주차(W33)를 봐도  → attendance {present 100, late 5, absent 4}
14주차(W36)를 봐도  → attendance {present 100, late 5, absent 4}   동일

그래서 "지난주 대비 출석률" 같은 문장을 만들 수 없다. 비교할 이전 주 값이 존재하지 않는다.

정리하면

항목5개 API 필드값S의 상세주간 리포트 사용
출결있음 (W·C·H)100.0 상수있음 (누적)값 보강 시 가능
과제있음 (W·C·H)0 + 미수집 선언있음 (누적)불가
퀴즈없음—있음 (누적)불가

이 값들의 원천은 LMS다

/sync/students의 출결·과제·퀴즈는 GOV-AI가 수집한 것이 아니라 LMS가 넘긴 데이터다. LMS-DOCS/10_데이터/외부_AI_코칭_API.md가 정의한 data-ingest-api가 원천이며, 양쪽이 같은 X-DE-API-KEY 헤더를 쓴다.

LMS data-ingest-api ──X-DE-API-KEY──▶ GOV-AI 수집 ──▶ /sync/students
  GET /ingest/v1/courses?include=activities
블록LMS가 주는 필드GOV-AI가 저장한 것
attendancepresent, late, earlyLeave, absent, excused5개 전부 (snake_case 변환)
assignmentstotal, submitted, supplementRequested, reviewDone, notSubmitted3개만

즉 GOV-AI는 우리가 준 값을 받아만 두고 주간 리포트에는 반영하지 않는다. 출결이 100.0인 것도 원천이 없어서가 아니라 집계 단계에서 쓰이지 않기 때문이다.

화면 설계에 미치는 결론

LMS-DOCS/30_설계/60_기능/기능_명세/P0_12_수강생_과정별_역량_리포트.md가 이미 원천을 나눠 놓았다.

P0-STU-DIAG-004 완료 기준: "지표는 퀴즈·과제 점수가 아니라 실습 행동 로그(정체·에러율·힌트 의존·재시도 간격) 기반임"

같은 문서가 구 competency 화면과의 차이를 데이터 원천으로 구분한다 — 구 화면은 "퀴즈·과제·출결·기록 집계", 진단 리포트는 "실습 단계 진행·에러·힌트·재시도 지표"다. 실제 API 응답이 이 구분과 일치한다. 출결·과제·퀴즈는 교육과정 허브의 출결/태도·과제·퀴즈 전용 탭이 담당한다.
