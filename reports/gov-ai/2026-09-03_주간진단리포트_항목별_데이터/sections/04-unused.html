4. 받지만 쓰지 않는 것

API 4가 주는 44필드 중 화면이 읽는 것은 25개다. 나머지를 쓰지 않는 이유는 넷으로 나뉜다.

분류필드쓰지 않는 이유
신원student_uuid · cohort_label · metrics_snapshot의 이름·기수·반·언어·UUID 7필드로그인한 본인 화면이라 다시 받을 이유가 없다
집계assignments_completed · attendance_rate · missing_fields값이 고정이거나 미수집이다 — 필드 정리 보고서 4장
운영id · week_label · risk_score · created_at · data_freshness레코드 관리용이다
강사용recommendations강사 권장 조치라 수강생 화면에 노출하지 않는다

안 쓰는 것과 못 받는 것은 다르다

위 표는 받았는데 쓰지 않는 것이다. 반대로 필요한데 받지 못하는 것이 셋 있다. 화면이 지금 상수나 임시 규칙으로 메우고 있는 자리다.

필요한 값지금 어떻게 메우나어디서 받아야 하나
총 단계 수 (진도의 분모)코드에 상수 10API 2의 summary.total_steps에만 있다. API 2를 함께 부르거나 API 4에 필드가 추가돼야 한다
강사 승인 여부마지막 주차만 미승인으로 두는 임시 규칙어디에도 없다. API 4에 승인 필드가 없고, API 2의 human_in_the_loop은 증명서 단위라 주차별이 아니다. 강사가 /feedback/approve로 승인해도 수강생 화면이 알 방법이 없다
기수 시작일코드에 2026-06-01응답은 ISO 주차만 준다. 기수 경과 주차로 바꾸려면 시작일이 필요한데 LMS에서 가져온다
셋 다 화면이 이미 그리고 있는 값이다. 상수와 임시 규칙으로 채워져 있어 화면만 보면 정상으로 보이지만, 다른 기수·다른 과정에서는 틀린 값이 된다. 근거와 요청 항목은 필드 정리 보고서 4.7에 있다.
top_error_types는 상위 3개만 온다. 실측에서 세 건의 합이 total_errors의 63.6%였고, 나머지 36.4%는 어느 응답에도 나타나지 않으며 "기타" 항목도 없다. 막대그래프를 그리면 합이 전체와 맞지 않는다.
