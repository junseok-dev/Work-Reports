4. 화면에 나오지 않는 값

API 4가 주는 44필드 중 화면이 값을 그리는 것은 25개다. 나머지를 "안 쓴다"로 묶으면 틀린다. 그리지 않을 뿐 없으면 화면이 아예 안 뜨는 값이 있고, 받았지만 정말 안 쓰는 값이 있고, 필요한데 못 받는 값이 있다. 넷으로 가른다.

4.1 그리지 않지만 없으면 화면이 안 뜬다

식별자는 화면에 나오지 않는다. 그렇다고 없어도 되는 값이 아니다. 어느 수강생의 이력인지 지정하는 것이 곧 호출이고 조회이므로, 이 값이 어긋나면 리포트가 통째로 비어 있다.

필드어디에 쓰이나없거나 어긋나면
userId
LMS user.id(UUID)		mock이 이력을 찾는 조회 키다.
DATALAKE_HISTORY[userId]		매칭 실패 → 빈 배열 → 리포트가 하나도 없는 화면이 뜬다
student_uuid
학번 12자리		실연동에서 요청 경로에 들어간다.
GET /reports/history/{uuid}		호출 자체가 성립하지 않는다
그래서 fixture의 식별자를 로그인 계정에 맞춰 바꿨다. 원본은 29기 정승(fd0ba10e-…)인데, LMS-FE 데모 계정은 34기 황수빈(f074a93b-…)이다. 원본 그대로 뒀다면 데모 계정으로 로그인했을 때 DATALAKE_HISTORY에서 키를 찾지 못해 진단 리포트 탭이 빈 화면이었을 것이다. 치환 내역은 mock 구성안 3장에 있다.

4.2 그리지 않지만 값이 맞아야 한다

이 화면은 이름·기수·반을 그리지 않는다. 로그인한 본인 화면이라 다시 보여줄 이유가 없다. 그렇다고 아무 값이나 넣어도 되는 것은 아니다 — mock은 시연 전체가 한 사람으로 읽혀야 하기 때문이다.

필드이 화면에서그래도 맞춰야 하는 이유
name — 수강생 이름그리지 않는다증명서·로스터 등 다른 화면은 황수빈으로 뜬다. 진단 리포트의 원천만 정승이면 같은 데모 안에서 두 사람이 된다
cohort · cohortId — 기수그리지 않는다기수 경과 주차를 계산할 때 기수 시작일과 짝이 맞아야 한다. 29기 데이터에 34기 시작일을 대면 주차가 어긋난다
group — 반그리지 않는다그룹 리포트(매니저용)와 대조할 때 필요하다
language — 실습 언어그리지 않는다그려서도 안 된다. 주간 리포트가 학생을 가리지 않고 python을 준다. 값 범위가 명세에 없어 실제 실습 언어인지 확인되지 않았다

4.3 받았지만 쓰지 않는다

여기부터가 진짜로 안 쓰는 값이다. 빠져도 화면은 그대로 뜬다.

분류필드쓰지 않는 이유
집계assignments_completed — 완료한 과제 수
attendance_rate — 출석률(%)
missing_fields — 수집하지 못한 항목의 이름		값이 고정이거나 미수집이다 — 필드 정리 보고서 5장
운영id — 리포트 레코드 식별자
week_label — 주차 표시 문자열
risk_score — 위험 점수 0~100
created_at — 레코드 생성 시각
data_freshness — 지표를 집계한 시각		레코드 관리용이다
강사용recommendations — 강사에게 주는 권장 조치강사 권장 조치라 수강생 화면에 노출하지 않는다

4.4 필요한데 받지 못한다

화면이 이미 그리고 있는 값인데 응답에 없어 상수나 임시 규칙으로 메우고 있는 자리다.

필요한 값지금 어떻게 메우나어디서 받아야 하나
총 단계 수 (진도의 분모)코드에 상수 10API 2의 summary.total_steps에만 있다. API 2를 함께 부르거나 API 4에 필드가 추가돼야 한다
강사 승인 여부마지막 주차만 미승인으로 두는 임시 규칙어디에도 없다. API 4에 승인 필드가 없고, API 2의 human_in_the_loop은 증명서 단위라 주차별이 아니다. 강사가 /feedback/approve로 승인해도 수강생 화면이 알 방법이 없다
기수 시작일코드에 2026-06-01응답은 ISO 주차만 준다. 기수 경과 주차로 바꾸려면 시작일이 필요한데 LMS에서 가져온다
셋 다 화면만 보면 정상으로 보이지만, 다른 기수·다른 과정에서는 틀린 값이 된다. 근거와 요청 항목은 필드 정리 보고서 5.7에 있다.
top_error_types는 상위 3개만 온다. 실측에서 세 건의 합이 total_errors의 63.6%였고, 나머지 36.4%는 어느 응답에도 나타나지 않으며 "기타" 항목도 없다. 막대그래프를 그리면 합이 전체와 맞지 않는다.
