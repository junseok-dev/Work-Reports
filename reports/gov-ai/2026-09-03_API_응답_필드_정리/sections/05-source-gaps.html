5. 출결·과제·퀴즈 — 5개 API 안에서는 어떻게 오나

검토 내내 이 셋을 두고 "온다"와 "없다"가 뒤집혔다. 명세서의 다섯 API만 놓고 보면 답이 단순하다 — 필드는 오는데 쓸 수 있는 값이 아니고, 퀴즈는 필드조차 없다. 셋 다 주간 진단 리포트에 넣을 수 없으며, 막히는 지점이 서로 다르다.

5.2 막히는 지점이 셋 다 다르다

"호출하면 값이 온다"와 "그 값을 쓸 수 있다"는 다르다. 어디서 막히는지가 항목마다 달라 말이 계속 엇갈렸다.

막히는 지점해당무슨 뜻인가
1값에 정보가 없다출결attendance_rate가 학생을 바꿔도 주차를 바꿔도 100.0이다. 값이 하나뿐이면 지표로서 구별력이 0이다. 게다가 missing_fields에 attendance가 없으므로 서버는 이 데이터를 받았다고 본다 — 결측으로 처리되지도 않는다
2서버가 미수집을 선언한다과제missing_fields: ["assignments"]. 여기서 0은 0건 제출이 아니라 안 받음이다. 서버가 스스로 알려주므로 오해할 여지는 없지만, 값이 없다는 사실은 그대로다
3필드가 아예 없다퀴즈다섯 응답 어디에도 quiz를 포함하는 키가 없다. 명세서 §4 필드 사전에도 없다. 있다·없다를 논할 것도 없이 계약에 들어 있지 않다

5.3 근거

출결 — 학생과 주차를 바꿔도 값이 하나다

API 1을 학생 다섯 명에게, API 4를 네 주차에 걸쳐 호출한 결과다.

API 1  학생 5명(정승·박상희·장규원·윤승혁·정예린)   attendance_rate  전원 100.0
API 4  정승 W33·W34·W35·W36                        attendance_rate  4주 전부 100.0
API 2  정승                                        attendance_rate  100.0

세 호출·다섯 학생·네 주차에서 관측된 값이 100.0 하나뿐이다. 실제 출결이 전원 만점일 가능성은 없으므로 집계가 동작하지 않는 것으로 본다. 다만 다섯 API 안에는 이를 대조할 수단이 없다 — 결석·지각 일수를 주는 필드가 없기 때문이다.

과제 — 응답이 스스로 미수집을 밝힌다

curl -X GET "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY"
  → metrics.assignments_completed : 0
     metrics.missing_fields       : ["assignments"]

같은 응답 안에 값과 그 값이 유효하지 않다는 표시가 함께 온다. 0을 제출 건수로 읽으면 제출한 학생을 미제출로 표시하게 된다. 이 선언이 있는 한 0은 쓸 수 없다.

퀴즈 — 전 응답을 훑어도 없다

API 1의 57필드(metrics 23), API 2의 39필드, API 3의 13필드, API 4의 43필드, API 5의 9필드를 전수 확인했다. quiz를 포함하는 키가 하나도 없다.

5.4 결론

항목판정이유무엇이 있어야 되나
출결못 한다값에 구별력이 없다attendance_rate가 학생·주차별로 실제 값을 반영하거나, 출석·지각·결석 일수가 주차별로 와야 한다
과제못 한다서버가 미수집 선언missing_fields에서 assignments가 빠지고 assignments_completed에 실제 건수가 들어와야 한다
퀴즈못 한다필드 자체가 없다/reports/weekly·/reports/history에 퀴즈 필드가 신설돼야 한다
셋 다 우리가 풀 수 있는 문제가 아니다. 계산으로 우회하거나 다른 값으로 대체할 방법이 다섯 API 안에 없다. 화면에 넣으려면 GOV-AI가 응답을 고쳐야 하고, 그때까지는 진단 리포트에서 뺀다. 출결·과제·퀴즈는 교육과정 허브의 전용 탭이 LMS에서 직접 가져와 담당한다.

5.5 화면 설계상으로는 이미 갈라져 있다

LMS-DOCS/30_설계/60_기능/기능_명세/P0_12_수강생_과정별_역량_리포트.md가 원천을 나눠 놓았다.

P0-STU-DIAG-004 완료 기준 — "지표는 퀴즈·과제 점수가 아니라 실습 행동 로그(정체·에러율·힌트 의존·재시도 간격) 기반임"

같은 문서가 구 competency 화면과의 차이를 데이터 원천으로 구분한다 — 구 화면은 "퀴즈·과제·출결·기록 집계", 진단 리포트는 "실습 단계 진행·에러·힌트·재시도 지표"다. 실제 API 응답이 이 구분과 정확히 일치한다. 다섯 API가 주는 쓸 만한 값은 전부 실습 행동 로그이고, 출결·과제·퀴즈는 오지 않거나 값이 비어 있다. 설계가 먼저 갈라놓은 선을 데이터가 그대로 따르고 있는 셈이다.
