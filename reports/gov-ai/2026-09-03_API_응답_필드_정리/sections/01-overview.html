1. 검증 개요

GOV-AI DataLake 명세서(REPORT-API-CALL.md v1.3)가 정의한 5개 API를 2026-09-03에 직접 호출해 실제 응답을 확인했다. 이 문서는 명세서의 다섯 엔드포인트만 다룬다 — 문서에 없는 엔드포인트는 계약 밖이라 언제 바뀌어도 이상하지 않으므로 근거로 쓰지 않는다. 주간 진단 리포트 화면이 어떤 값을 쓸 수 있고 어떤 값을 쓸 수 없는지를, 호출 명령과 응답 값을 근거로 정리한다.

대상 https://datalake.isitsoft.kr/api/v1 · API v1.0.0 · 인증 헤더 X-DE-API-KEY. 검증 수강생은 명세서 예시와 같은 100030029410(정승, 29기)이며, 화면 구성 예시에는 데모 계정 100051503818(황수빈, 34기)을 쓴다.

이 문서의 구성

호출에서 시작해 필드, 그리고 쓸 수 있는지 판단 순으로 간다.

장다루는 것여기서 답하는 질문
2장다섯 엔드포인트를 어떤 명령으로 불렀고 응답의 최상위 구조가 어떤가어떻게 부르는가 · 무엇이 통째로 오는가 · 응답의 최상위가 어떻게 생겼나
3장응답 필드 전체 사전 — 각 필드의 의미·타입·실측값이 필드가 무슨 뜻인가 · 어떤 값이 왔는가 · 호출마다 이름이 왜 다른가
4장값이 어떤 모양으로 오는가 — 형식·단위·표기이름은 어떻게 오는가 · 시각이 왜 세 형식인가 · 숫자가 반올림돼 있나 · "없다"를 어떻게 구분하나
5장출결·과제·퀴즈 — 어떤 통계가 되고 무엇이 안 되는가필드는 오는데 왜 못 쓰는가 · 그래도 낼 수 있는 통계는 무엇인가 · GOV-AI에 무엇을 요청해야 하는가
화면 항목마다 어떤 값이 들어가 어떤 숫자·문장이 되는지는 이 보고서가 아니라 주간 진단 리포트 항목별 데이터에서 다룬다.

호출 환경

이 문서의 모든 명령은 아래 환경변수를 전제한다. 키는 저장소에 두지 않는다.

export DE_API_KEY="<명세서 1.1의 X-DE-API-KEY>"
export B="https://datalake.isitsoft.kr/api/v1"
export U="100030029410"
export PYTHONIOENCODING=utf-8

응답을 읽을 때는 PYTHONIOENCODING=utf-8과 --no-ensure-ascii가 둘 다 있어야 한글이 보인다. 앞이 없으면 콘솔 코드페이지에서 깨지고, 뒤가 없으면 \uc815\uc2b9 형태로 이스케이프된다.

curl -sS "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY" \
  | python -m json.tool --no-ensure-ascii
Windows 주의 Git Bash·PowerShell 모두 curl.exe에 명령행 인자를 넘길 때 한글을 시스템 코드페이지(CP949)로 변환한다. 한글이 든 요청 본문을 -d로 인라인 전달하면 서버가 UTF-8로 디코딩하지 못해 400 There was an error parsing the body가 난다. 본문은 파일로 저장해 --data-binary @file로 보내야 한다. macOS·Linux에서는 명세서 예시가 그대로 동작한다.
