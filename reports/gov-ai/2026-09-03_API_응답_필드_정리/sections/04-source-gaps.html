4. 출결·과제·퀴즈 — 무엇이 되고 무엇이 안 되는가

이 셋은 현재 주간 진단 리포트에 들어가지 않는다. 그런데 호출하면 값이 오기 때문에 검토 내내 "있다"와 "없다"가 뒤집혔다. 어디서 무엇이 오는지, 왜 못 쓰는지, 그래도 무엇은 되는지를 호출과 값으로 가른다.

4.2 "온다"와 "쓸 수 있다"는 다르다

말이 엇갈린 이유는 막히는 지점이 항목마다 다르기 때문이다. 네 가지를 구분하지 않으면 같은 항목을 두고 "온다"와 "없다"가 둘 다 맞는 말이 된다.

막히는 지점해당 항목무슨 뜻인가
1부르는 곳이 다르다퀴즈명세서는 5개 API만 다루는데 실제 서버의 /openapi.json에는 24개가 있다. "퀴즈가 왔다"는 /sync/students를, "퀴즈가 없다"는 5개 API를 가리킨 말이라 둘 다 참이었다.
2필드는 있는데 값이 틀렸다출결attendance_rate가 학생과 무관하게 전부 100.0이다. missing_fields에 attendance가 없으므로 서버는 받았다고 본다. 결측이 아니라 틀린 값이라 더 위험하다.
3서버가 미수집을 선언한다과제missing_fields: ["assignments"]. 여기서 0은 0건 제출이 아니라 안 받음이다. 서버가 스스로 알려주는 정직한 처리이므로, 이 선언을 보면 오해하지 않는다.
4주차로 나눌 수 없다셋 다/sync/students는 last_synced_at 시점의 누적 현재값이다. 주차 파라미터가 없어 "이번 주"나 "지난주 대비"를 만들 수 없다.

출석만 세도, 지각·조퇴를 출석으로 쳐도 100이 나오는 계산은 없다. 상수라고 볼 수밖에 없다.

과제 — 같은 학생인데 호출마다 값이 다르다

curl -X GET "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY"
  → metrics.assignments_completed : 0
     metrics.missing_fields       : ["assignments"]

curl -X GET "$B/sync/students?limit=200" -H "X-DE-API-KEY: $DE_API_KEY"
  → assignments {"total": 10, "submitted": 9, "not_submitted": 1}

황수빈 한 명이 한쪽에서는 0건, 다른 쪽에서는 9건 제출이다. missing_fields가 앞의 0을 미수집이라고 알려주므로 뒤가 맞다. 이 선언을 보지 않고 0을 쓰면 제출한 학생을 미제출로 표시하게 된다.

누적 — 주차를 바꿔도 같은 값이 온다

11주차(W33)를 봐도  → attendance {present 100, late 5, absent 4}
14주차(W36)를 봐도  → attendance {present 100, late 5, absent 4}   동일

4.5 이 값들의 원천은 LMS다

/sync/students의 출결·과제·퀴즈는 GOV-AI가 수집한 것이 아니라 LMS가 넘긴 데이터다. LMS-DOCS/10_데이터/외부_AI_코칭_API.md가 정의한 data-ingest-api가 원천이며, 양쪽이 같은 X-DE-API-KEY 헤더를 쓴다.

LMS data-ingest-api ──X-DE-API-KEY──▶ GOV-AI 수집 ──▶ /sync/students
  GET /ingest/v1/courses?include=activities
블록LMS가 주는 필드GOV-AI가 저장한 것
attendancepresent, late, earlyLeave, absent, excused5개 전부 (snake_case 변환)
assignmentstotal, submitted, supplementRequested, reviewDone, notSubmitted3개만
quizzestotalOpen, attempted, finalized, avgScorePct2~3개만
qna · projects · troubleshooting전부 제공사용 안 함

즉 GOV-AI는 우리가 준 값을 받아만 두고 주간 리포트에는 반영하지 않는다. 출결이 100.0인 것도 원천이 없어서가 아니라 집계 단계에서 쓰이지 않기 때문이다.

4.6 화면 설계상으로는 이미 갈라져 있다

LMS-DOCS/30_설계/60_기능/기능_명세/P0_12_수강생_과정별_역량_리포트.md가 원천을 나눠 놓았다.

P0-STU-DIAG-004 완료 기준 — "지표는 퀴즈·과제 점수가 아니라 실습 행동 로그(정체·에러율·힌트 의존·재시도 간격) 기반임"

같은 문서가 구 competency 화면과의 차이를 데이터 원천으로 구분한다 — 구 화면은 "퀴즈·과제·출결·기록 집계", 진단 리포트는 "실습 단계 진행·에러·힌트·재시도 지표"다. 실제 API 응답이 이 구분과 일치한다. 출결·과제·퀴즈는 교육과정 허브의 출결/태도·과제·퀴즈 전용 탭이 담당한다. 진단 리포트에 넣는다면 그 탭들과 같은 원천(/sync/students 또는 LMS 직접 조회)을 써야 값이 어긋나지 않는다.
