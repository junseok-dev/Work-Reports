2. API 1~5 호출과 응답

명세서 §2의 다섯 엔드포인트를 순서대로 호출한 결과다. 각 호출의 실제 명령과 응답의 최상위 구조를 기록한다. 명세서에 정의된 다섯 개가 전부다. 필드 하나하나는 3장에서 편다.

API 1. 주간 AI 학습 맞춤 진단 리포트

curl -X GET "$B/reports/weekly/$U?format=json" -H "X-DE-API-KEY: $DE_API_KEY"

최상위 10개 블록이 온다.

studentUuid · year_week · week_no · week_label · week_range · cached
metrics · diagnosis · weakness · risk

metrics는 24필드다. 이 목록이 진단 리포트가 쓸 수 있는 지표의 전부다.

studentUuid  userId  name  cohortId  cohort  group  language
steps_completed  current_step  stalled_days_on_current_step  days_since_last_activity
active_days_count  total_runs  total_errors  error_per_run
hint_requests_count  hint_per_active_day  avg_retry_gap_min  max_retry_gap_min
top_error_types  assignments_completed  attendance_rate  data_freshness  missing_fields

API 2. LMS 연동용 역량 증명서

curl -X GET "$B/certificate/$U" -H "X-DE-API-KEY: $DE_API_KEY"
version · issue_timestamp · student · summary · technical_proof
project_and_portfolio · ai_analysis_narrative · human_in_the_loop

project_and_portfolio 블록은 API 1과 필드명이 다르다.

"project_and_portfolio": {
  "completed_assignments": 0,      // API 1은 assignments_completed
  "attendance_rate": 100.0,
  "collaboration_score": 85.0
}

summary.total_steps = 10은 이 API에만 있어, 진행률을 10/10으로 표시하려면 여기서 가져오거나 상수로 두어야 한다.

API 3. 온디맨드 수준 진단

curl -X POST "$B/analysis/diagnose/$U" -H "X-DE-API-KEY: $DE_API_KEY"

최상위 10필드가 평탄하게 온다. API 1의 diagnosis 블록과 같은 구성이다.

studentUuid · grade · confidence · grade_rationale · weak_patterns · risk_flags
recommendations_for_instructor · suggested_feedback_draft · analyzed_at · model_meta
지표가 아예 없다. total_runs·error_per_run 같은 정량 값이 오지 않는다. 진단 텍스트만 반환하는 엔드포인트다.

API 4. 주차별 리포트 이력

curl -X GET "$B/reports/history/$U?limit=5" -H "X-DE-API-KEY: $DE_API_KEY"

배열로 오며 항목당 20필드다. API 1과 필드명이 다르다.

API 1 (weekly)API 4 (history)
studentUuidstudent_uuid
diagnosis.recommendations_for_instructorrecommendations
diagnosis.suggested_feedback_draftfeedback_draft
risk.statusrisk_status
diagnosis.model_meta.provider · .modelllm_provider · llm_model
4개 블록 중첩전부 평탄화 + metrics_snapshot · markdown_content

주차별 metrics_snapshot을 열면 주차마다 필드 수가 다르다.

2026-W33  metrics_snapshot   7개 필드
2026-W34  metrics_snapshot   7개 필드
2026-W35  metrics_snapshot  24개 필드
2026-W36  metrics_snapshot  24개 필드

과거 두 주차는 steps_completed · current_step · total_runs · total_errors · error_per_run · active_days_count · attendance_rate 7개로 축약된다. 힌트·재시도·정체·에러 유형과 신원 필드가 사라진다.

API 5. 강사 피드백 승인

cat > payload.json <<'EOF'
{
  "studentUuid": "100030029410",
  "approved_by": "[TEST] 필드 확인",
  "feedback_text": "[TEST] API 5 응답 필드 확인용",
  "status": "APPROVED"
}
EOF

curl -X POST "$B/feedback/approve" -H "X-DE-API-KEY: $DE_API_KEY"   -H "Content-Type: application/json" --data-binary @payload.json
{"status": "SUCCESS", "log_id": "fb_20260903103059_100030029410", "approved_by": "[TEST] 필드 확인"}

응답은 3필드뿐이다. 승인 로그가 누적 생성되고 삭제 API가 없으므로, 검증 호출에는 [TEST] 표기를 붙여 나중에 골라낼 수 있게 했다.

log_id의 시각 103059는 KST다. 같은 순간 다른 응답의 analyzed_at·data_freshness·issue_timestamp는 UTC로 온다. 한 서비스 안에서 타임존이 섞여 있다.
