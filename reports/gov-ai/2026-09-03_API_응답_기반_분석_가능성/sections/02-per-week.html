API 4가 주는 한 행(metrics_snapshot)만으로 계산되는 값이다. 지금 화면이 쓰는 8칸 외에 일곱 가지를 더 만들 수 있다.

curl -X GET "$B/reports/history/$U?limit=5" -H "X-DE-API-KEY: $DE_API_KEY"
파생 지표계산W36 실측무엇을 말해주나
단계당 실행 횟수total_runs ÷ steps_completed4,946 ÷ 10 = 494.6한 단계를 넘기는 데 몇 번 시도했나. 시행착오의 양
활동 밀도active_days_count ÷ 77 ÷ 7 = 1.00그 주에 며칠이나 손을 댔나. 학습 리듬
에러 집중도top3 합 ÷ total_errors304 ÷ 478 = 63.6%에러가 몇 가지에 몰려 있나. 높으면 특정 개념에 막힌 것
최다 에러 비중top1 ÷ total_errors105 ÷ 478 = 22.0%한 가지가 얼마나 지배적인가
실행 대비 힌트hint_requests_count ÷ total_runs286 ÷ 4,946 = 5.8%몇 번 실행할 때마다 힌트를 여나
에러당 힌트hint_requests_count ÷ total_errors286 ÷ 478 = 0.60막혔을 때 스스로 보는 비율. 1에 가까울수록 에러마다 힌트
진도율steps_completed ÷ total_steps10 ÷ 10 = 100%분모가 API 2에만 있어 지금은 상수 10을 쓴다
에러 집중도의 분모에 주의가 필요하다. top_error_types는 상위 3개만 오므로 63.6%는 "상위 3종이 전체의 63.6%"라는 뜻이고, 나머지 36.4%가 몇 종인지는 알 수 없다. 원형 그래프로 그리면 합이 100이 되지 않는다.
