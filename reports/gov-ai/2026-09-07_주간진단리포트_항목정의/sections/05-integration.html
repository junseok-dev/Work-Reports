수강생 본인 조회

FE는 주차 목록과 선택 주차 상세를 분리해 호출합니다. 상세 응답에 운영이 발송한 피드백이 있으면 맨 아래에 표시하고, 미발송 값은 숨깁니다.

  • GET /student/course/diagnosis/my-reports — 완료 주차 목록과 추세 재료
  • GET /student/course/diagnosis/my-reports/{week} — 선택 주차 본문·직전 주차 비교·선택적 instructorFeedback
  • instructorFeedback.sentAt이 있어야 본문·작성자·발송 시각을 수강생에게 표시
  • 확신도 값은 계약과 내부 화면 모델에는 유지하지만 수강생 UI에서는 숨김

강사·운영 관리

지도자용 학생 목록·학생별 주차·상세와 피드백 쓰기 API는 FE 요청 계약으로 구현되어 있으며, 실 BE 구현은 대기 중입니다.

역할조회변경수강생 공개
강사담당 기수 학생·주차·상세역할 전용 임시저장, 저장 완료 후 운영 알림직접 공개하지 않음
운영운영 범위 학생·주차·상세임시저장·저장, 현재 주차 재분석, 주차 일괄 발송일괄 발송으로 공개본 생성
수강생본인 완료 주차만없음발송본만 열람

로컬 mock과 실서버 전환

로컬 MSW는 세 역할의 조회와 임시저장 → 저장 완료 → 일괄 발송 → 수강생 공개 흐름을 같은 상태로 재현합니다. 브라우저 저장소를 사용해 강사·운영의 역할별 임시저장본, 공유 저장본, 운영 알림, 발송본을 구분합니다.

  • 기본 로컬 모드: 진단리포트 handler가 수강생·강사·운영 경로를 처리
  • VITE_REAL_DIAGNOSIS=true: 진단 handler를 등록하지 않고 요청을 실서버로 전달
  • 실서버 요청 실패를 mock 데이터로 대체하는 fallback은 두지 않음

남은 연동 경계

GOV-AI 자동 수집, 지도자용 전용 API, 저장·발송 영속화, 수강생별 알림 fan-out은 BE 후속 작업입니다. 로컬 mock 성공은 이 서버 기능들의 완료 증거가 아닙니다.

원천의 userId와 LMS 로그인 계정이 다를 수 있으므로 자동 수집 시 공통 식별자인 student_uuid로 계정을 매핑해야 합니다.
