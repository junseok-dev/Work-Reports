서비스가 맡는 역할

교육 상담 자동화

과정 소개, 커리큘럼, 지원 대상, 일정·비용·장소, 입과 절차와 운영 규정을 한국어 상담 말투로 안내합니다.

승인 정보 기반 답변

관리자가 승인한 문서와 FAQ, 공식 홈페이지의 최신 일정에서 근거를 찾은 뒤 답변합니다.

사람 상담 연결

취소·환불·일정 변경, 사용자의 명시적 요청 등 개별 확인이 필요한 질문에는 상담 연결 버튼을 제공합니다.

운영 관점의 핵심: 문서·FAQ·답변 규칙·관리자 권한은 관리자 화면에서 관리할 수 있습니다. 화면 구조, 판단 로직, 배포 방식 변경만 개발 작업이 필요합니다.

상담 연결의 현재 의미

149건은 상담 연결 버튼이 포함된 응답 수입니다. 이 중 취소·환불·일정 변경 안내는 41건, 그 외 상담 연결·제안은 108건입니다.

현재 측정할 수 없는 것

페이지 방문자, 상담 버튼 클릭, 실제 상담 시작과 완료는 아직 로그에 없습니다. 따라서 방문→채팅→상담 전환율은 계산할 수 없습니다.

해석 주의: 전체 86일 중 실제 대화가 있었던 날은 64일입니다. 초기 특정 날짜에 기록이 집중됐고 테스트·실사용 구분값이 없으므로, 이 수치를 “방문자 수”나 “실제 사람 수”로 표현하지 않습니다.

04

지식과 관리자 운영

운영자는 대부분의 콘텐츠와 답변 기준을 코드 배포 없이 관리자 화면에서 변경할 수 있습니다.

승인 문서

과정 설명, 커리큘럼과 규정의 상세 근거입니다. 검토·승인된 버전만 검색에 사용합니다.

공식 홈페이지

모집 기수, 개강일, 시간, 장소와 비용을 마지막 성공 후 24시간 주기로 갱신합니다.

FAQ

반복 질문에 사용하는 기준 답변입니다. 유사 표현과 참고 문서를 함께 설정할 수 있습니다.

답변 규칙

말투, 답변 범위, 취소·상담 연결과 오류 안내 기준을 관리합니다.

06

현재 한계와 개선 우선순위

새 기능을 많이 나열하기보다 서비스 성과를 제대로 측정하고 중요한 상담을 놓치지 않는 데 우선순위를 둡니다.

우선순위 1

방문·상담 전환 측정

페이지 진입, 채팅 시작, 상담 버튼 클릭과 실제 상담 시작을 구분해 기록합니다. 최소 정보만 수집하고 보존 기간을 함께 정합니다.

우선순위 2

중요 상담 확인 화면

취소·환불·안전 차단·상담 연결을 별도 목록으로 모으고 미확인·처리 중·완료 상태와 담당자를 기록합니다.

우선순위 3

로그 기반 답변 개선

오답·정보 부족·잘못된 분기 사례를 문서, FAQ, 프롬프트, 코드 문제로 나눠 수정하고 회귀 질문에 추가합니다.

우선순위 4

비용 집계 분리

AWS 계정 전체 비용과 챗봇 비용을 구분하고, OpenAI 실제 청구 데이터를 사용해 월 비용과 세션당 비용을 계산합니다.

완료 판단 기준

  • 동일 기간의 관리자 지표와 원본 로그 집계가 일치합니다.
  • 방문자와 대화 참여 세션, 상담 버튼 표시와 실제 상담 시작을 혼용하지 않습니다.
  • 중요 상담을 별도 목록에서 찾고 처리 상태를 기록할 수 있습니다.
  • 개선한 질문과 기존 핵심 질문이 함께 회귀 검증을 통과합니다.
  • 배포 후 health, 대표 질문, 관리자 로그인과 상담 연결을 확인합니다.
07

운영 소유권과 담당자 변경

챗봇 소스는 담당자의 개인 GitHub 저장소에서 관리합니다. 담당자가 바뀔 때는 새 저장소 복제보다 GitHub Repository Transfer를 우선합니다.

평상시

차기 담당자를 collaborator로 미리 등록하고, 코드와 관리자 운영을 최소 2명이 이해하도록 합니다.

담당자 변경 시

저장소 전체를 차기 담당자의 개인 GitHub 계정으로 이전해 커밋·이슈·설정의 연속성을 유지합니다.

이전 후

GitHub Secrets, EC2 runner, 서버 작업 폴더의 origin과 첫 배포를 차례로 확인합니다.

빠른 이관 체크리스트

  1. 차기 담당자의 저장소·AWS·OpenAI·Google·EC2 접근 권한을 먼저 확인합니다.
  2. RDS 백업, S3 데이터와 ENCRYPTION_KEY의 복구 가능성을 확인합니다.
  3. GitHub Repository Transfer를 실행하고 차기 담당자가 수락합니다.
  4. Actions Secrets와 self-hosted runner 상태를 확인합니다.
  5. EC2와 개발 PC의 origin을 새 저장소 주소로 변경합니다.
  6. 첫 배포 후 사용자 채팅, 관리자 로그인, 문서 검색과 상담 연결을 점검합니다.
  7. 모든 확인이 끝난 뒤 기존 담당자의 권한을 정리합니다.

비밀정보 원칙: API 키, DB 접속 문자열과 암호화 키의 실제 값은 이 보고서나 Git 저장소에 기록하지 않습니다. 특히 ENCRYPTION_KEY는 기존 암호화 데이터를 복구하는 데 필요하므로 승인된 비밀 저장소에 별도 보관합니다.

이 문서는 공개 공유용 요약본입니다. 개인정보, 실제 비밀값, 내부 전용 접속정보와 원문 대화는 포함하지 않습니다.
