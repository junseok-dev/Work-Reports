증상별 원인 후보와 복구 순서
증상주요 원인확인안전한 조치
관리자 전체 데이터가 로드되지 않음세션 만료(401), 백엔드 중단, RDS 연결 실패, 다섯 병렬 API 중 하나의 500 오류브라우저 Network에서 /api/admin/sessions, documents, faqs, prompts, logs를 개별 확인합니다.401은 다시 로그인합니다. 500은 systemd 로그와 DATABASE_URL·RDS 상태·보안그룹을 확인하고 서비스 복구 후 새로고침합니다.
저장 버튼을 눌러도 저장되지 않음필수값·형식 오류(400), 권한 없음(403), 대상 없음(404), 중복 키(409), RDS 쓰기 실패(500)Network의 응답 status와 detail, 관리자 감사 로그, RDS 여유 공간·연결 상태를 확인합니다.검증 오류를 먼저 고칩니다. 시스템 테이블을 직접 SQL로 우회 수정하지 말고 해당 전용 메뉴에서 다시 저장합니다.
PDF·MD 업로드 또는 승인 반영이 실패함PDF 변환·UTF-8 오류, S3 권한·버킷, RDS 쓰기 오류. FAQ 변환·승인 재색인 단계라면 OpenAI 키·한도 오류문서 상태가 uploaded → parsing → embedding → review → ready 중 어디에서 failed가 됐는지 processing log와 error message를 봅니다.원인을 해결한 뒤 같은 파일을 다시 업로드합니다. PDF 변환 문제면 검토한 Markdown으로 등록하고, 승인 실패면 OpenAI·S3를 복구한 뒤 다시 승인하거나 재색인합니다.
승인한 새 문서가 답변에 나오지 않음문서가 ready/is_active가 아님, 원문 S3 읽기 실패, FAISS 불일치, 질문이 다른 문서로 검색됨문서 상태·활성 버전, S3 document.md, EC2의 두 FAISS 파일과 processing log를 확인합니다.승인 상태를 바로잡고 “FAISS 인덱스 재구성”을 1회 실행한 뒤 새 질문과 회귀 질문을 다시 시험합니다.
재시작 후 문서 검색이 비거나 FAISS가 로드되지 않음AWS_S3_BUCKET·prefix 오류, IAM 권한 부족, index.faiss/index.pkl 일부 유실, 임베딩 모델 불일치S3의 document-chatbot/faiss/, EC2 로컬 파일, AWS 자격 증명과 로그를 확인합니다.올바른 S3 설정을 복구하고 승인 문서에서 전체 인덱스를 재생성합니다. 임베딩 모델은 이전 값으로 복구하거나 전체 재인덱싱합니다.
관리자 데이터가 빈 문자열로 보임ENCRYPTION_KEY가 비었거나 기존 암호문을 만든 키와 다름배포 전후 Secret 변경 이력, 서버 환경설정과 암호화 건수를 확인합니다.복호화·마이그레이션·재저장을 중지하고 정확한 기존 키를 복구한 뒤 서비스를 재시작합니다. 임의 새 키로 덮지 않습니다.
모델 목록 또는 모델 변경 실패OpenAI 401·권한·네트워크 오류, 선택 모델 미지원, RDS 저장 실패OpenAI Project 키와 모델 접근권한, Network 응답과 systemd 로그를 확인합니다. 목록 조회 실패 시 화면에 제한된 fallback 목록이 보일 수 있습니다.직전 정상 모델로 되돌리고 키·권한을 복구합니다. 모델 변경과 임베딩 변경을 같은 작업으로 처리하지 않습니다.
FAQ를 저장했지만 답변이 이상함FAQ key·유사 표현·내용 오류, 자동 재색인 실패, 프롬프트 재서술 영향FAQ 원문과 processing/system 로그, 실제 검색 경로와 LangSmith trace를 확인합니다.FAQ 내용을 수정하고 자동 재색인을 기다린 뒤 원문·줄임말·변형 질문을 시험합니다. 필요하면 수동 재색인을 1회 실행합니다.
배포 후 설정이 원래대로 돌아감deploy.yml이 backend/.env를 새로 생성해 서버에서만 바꾼 값을 덮어씀GitHub Actions 로그, Secrets와 배포 후 .env 항목 이름을 비교합니다.지속돼야 하는 값은 GitHub 배포 설정을 단일 기준으로 만듭니다. 단, 생성 모델은 RDS app_settings가 우선이므로 관리자 화면 값을 확인합니다.
