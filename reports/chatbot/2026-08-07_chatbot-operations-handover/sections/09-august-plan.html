01

로그 기반 답변 개선

실제 질문·답변 기록에서 오답, 정보 부족, 잘못된 분기와 반복 상담 연결 사례를 찾아 문서·FAQ·프롬프트·처리 로직을 보완합니다.

02

운영 대시보드

관리자 첫 화면에서 기간별 대화 참여 세션, 질문 수, 답변 방식, 상담 연결과 오류 추이를 바로 확인하도록 만듭니다.

03

중요 상담 집중 확인

04

사용자·관리자 UI 개선

채팅 사용 흐름과 관리자 정보 구조를 정리하고 모바일·데스크톱에서 주요 상태와 버튼이 명확하게 보이도록 개선합니다.

1. 대화 로그 기반 답변 품질 개선

로그에서 분류할 문제 유형

  • 최신 문서가 있는데도 오래되거나 다른 정보를 답한 경우
  • 관련 FAQ·문서를 찾지 못해 대체 안내로 끝난 경우
  • FAQ, 문서 검색, 상담 연결 중 잘못된 경로를 선택한 경우
  • 질문의 핵심을 놓치거나 답변이 지나치게 길고 반복적인 경우
  • 취소·안전 문제·사람 확인이 필요한데 상담 연결이 누락된 경우

수정과 검증 방법

  • 콘텐츠 문제는 문서·FAQ, 말투와 원칙은 프롬프트에서 우선 수정
  • 검색·분류 자체의 문제만 코드 로직으로 수정
  • 실제 실패 질문과 표현을 바꾼 질문을 회귀 질문 세트에 추가
  • 수정 전·후 답변, 처리 방식, 응답 시간과 LLM 비용을 함께 비교
  • 배포 후 새 오류·fallback·상담 연결 비율을 일정 기간 관찰

2. 관리자 대시보드에 표시할 이용 지표

영역표시 항목표시 방법집계 기준·주의
이용 규모대화 참여 세션, 질문·답변 수, 세션당 평균 질문 수오늘·최근 7일·최근 30일 카드와 이전 기간 대비 증감현재는 메시지를 보낸 고유 세션 기준이며 실제 사람 수와 같지 않을 수 있음
방문 현황페이지 방문 수, 고유 방문 세션, 채팅 시작 전환율일별 추이와 방문 → 채팅 시작 흐름실제 방문자 수를 보려면 별도의 방문 이벤트 수집 기능을 먼저 추가해야 함
답변 방식FAQ, 문서·LLM, 상담 연결, 대체 안내, 안전 차단건수·비율 카드와 일별/월별 누적 그래프사용자에게 전달된 최종 처리 방식 기준으로 집계
중요 상담취소·환불·일정 변경, 안전 차단, 상담 직원 연결미확인 건수 강조 표시와 상세 목록 바로가기버튼 표시와 실제 상담 시작은 다르므로 클릭·전환 이벤트를 별도로 기록
품질·장애실패, fallback, 평균 응답 시간, 반복 오류경고 카드, 추이 그래프, 최근 오류 목록정상 범위와 경고 기준은 초기 운영 데이터를 보고 확정
비용LLM 호출 비용과 일·월 예상액기간 합계, 일평균, 월말 예상치OpenAI 비용과 AWS 계정 비용의 집계 범위를 구분해 표시

‘이용자 수’ 표기 원칙: 방문 추적 기능이 배포되기 전에는 대시보드에 ‘방문자’라고 표시하지 않고 대화 참여 세션으로 표시합니다. 실제 방문자 수가 필요하면 페이지 진입, 채팅 시작, 상담 버튼 클릭 이벤트를 최소 정보로 기록하고 보존 기간과 개인정보 처리 기준을 함께 정해야 합니다.

3. 취소·안전·상담 연결 확인 화면

중요 사례가 전체 대화 로그에 섞이지 않도록 관리자 대시보드의 ‘확인 필요’ 영역에서 바로 조회하고 처리할 수 있게 합니다.

알림 범위: 8월 말 목표는 관리자 화면에서 미확인 중요 건수를 강조하고 상세 내용을 빠르게 찾는 데 둡니다. 이메일·Slack 등 외부 실시간 알림이 추가로 필요하면 수신자, 근무 시간, 개인정보 노출 범위와 오탐 대응 기준을 합의한 뒤 별도 작업으로 진행합니다.

4. UI 개선 범위

대상개선 방향필수 확인
사용자 채팅 화면첫 질문 안내, 추천 질문, 답변 구획, 출처 링크, 상담 연결 버튼과 오류·재시도 안내를 명확하게 정리모바일 입력창, 긴 답변, 링크, 키보드 사용, 로딩·오류 상태
관리자 첫 화면핵심 이용 지표와 미확인 중요 상담을 상단에 배치하고 기간 필터와 상세 화면 이동 경로 제공수치 기준, 필터 적용, 빈 데이터·로딩·오류 상태
관리자 목록 화면상태·종류·발생 시각을 색상뿐 아니라 텍스트와 아이콘으로 구분하고 검색·정렬·페이지 이동 개선작은 화면, 많은 행, 긴 질문, 개인정보 마스킹
공통 디자인흰색 배경과 검은색 본문을 기본으로 제목·버튼·경고의 위계를 통일명도 대비, 포커스 표시, 클릭 영역, 데스크톱·모바일 반응형

최종 완료 조건

  • 로그에서 선정한 개선 질문이 기대 답변을 내고 기존 핵심 질문 회귀 테스트를 통과한다.
  • 관리자 대시보드의 동일 기간 수치가 원본 대화 로그 집계와 일치한다.
  • 취소·안전 차단·상담 연결 건을 별도 목록에서 찾고 원문·답변·처리 상태를 확인할 수 있다.
  • 실제 방문자 수와 대화 참여 세션을 혼용하지 않고, 방문 추적을 구현한 경우 이벤트 정의와 개인정보 기준을 문서화한다.
  • 사용자와 관리자 주요 화면이 모바일·데스크톱에서 정상 작동하고 색상 없이도 상태를 구분할 수 있다.
  • 배포 후 health, 대표 질문, 관리자 로그인, 대시보드, 상담 연결 회귀 점검을 완료한다.
  • 최종 커밋·배포일·미완료 항목을 기록하고 신규 담당자가 주요 운영 작업을 직접 실습한다.
