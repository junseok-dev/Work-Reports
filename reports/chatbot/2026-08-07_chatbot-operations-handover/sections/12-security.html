계정·비밀정보 인계

이 보고서에는 비밀번호, API 키, 데이터베이스 접속 정보를 기록하지 않습니다. 실제 값 대신 회사가 승인한 보관 위치와 접근 권한을 인계합니다.

인계 원칙

새 담당자는 개인 계정이나 퇴사자의 도움 없이 필요한 시스템에 접근할 수 있어야 합니다. 계정은 가능하면 회사 명의로 전환하고, 최소 2명 이상의 회사 관리자가 복구 권한을 보유하도록 구성합니다.

가장 중요한 키: ENCRYPTION_KEY를 잃으면 이미 암호화된 FAQ·프롬프트·문서·대화 내용을 복구할 수 없습니다. 소스 코드와 분리된 회사 관리 비밀 저장소에 복구 가능한 형태로 보관하고, 키 교체는 데이터 마이그레이션 계획 없이 진행하지 않습니다.

현재 보안 동작

관리자 인증

Google ID Token을 서버에서 검증하고, ADMIN_EMAIL 또는 admin_users에 등록된 이메일만 HS256 JWT를 발급받습니다.

저장 데이터 암호화

채팅 내용은 항상 암호화되며, FAQ·프롬프트·문서는 카테고리별 설정에 따라 enc:: 접두사의 Fernet 암호문으로 저장됩니다.

관리 작업 추적

문서·FAQ·프롬프트 등 주요 관리자 작업은 admin_audit_logs에 행위자·대상·시각과 함께 기록됩니다.
