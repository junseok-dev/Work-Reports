관리자가 실제로 하는 일

관리자 페이지에서 등록된 회사 Google 계정으로 로그인합니다. 한 번 로그인하면 최대 8시간 동안 사용할 수 있습니다.

초기 인수 시 우선 확인 메뉴

문서 검토에서 자료 반영 절차를, FAQ 관리에서 반복 질문 수정 방법을, 로그/내보내기에서 실제 상담 기록 조회 방법을, 권한 관리에서 담당자 등록 절차를 확인합니다. 데이터 관리·DB 브라우저·암호화 설정은 영향 범위가 크므로 담당 개발자와 함께 확인하는 것을 권장합니다.

문서 검토 주요 메뉴

회사 문서를 올리고 내용을 검토한 뒤 승인·반려합니다. 변경된 검색 목록도 여기에서 다시 생성합니다.

FAQ 관리 주요 메뉴

자주 묻는 질문과 답변을 추가·수정·삭제하고, 비슷한 표현으로 검색될 수 있도록 관련 단어를 설정합니다.

프롬프트 주의

상담 말투, 취소·사람 상담 연결 문구, 오류 안내 등 답변 작성 규칙을 관리합니다.

로그/내보내기 주요 메뉴

실제 질문과 답변, 처리 오류, 관리자 작업 이력을 조회하고 Excel 파일로 내려받습니다.

데이터 관리

별도의 표 형태 운영 데이터를 만들고 열·행을 관리하며 Excel 파일을 가져오거나 내보냅니다.

DB 브라우저 개발자 권장

운영 데이터베이스를 직접 조회·수정·삭제합니다. 잘못된 변경의 영향이 크므로 일반 콘텐츠 수정에는 사용하지 않습니다.

설정 주의

답변 작성에 사용할 AI 모델과 FAQ·답변 규칙·문서의 암호화 여부를 관리합니다.

권한 관리 주요 메뉴

관리자 이메일을 추가·제거하고 최상위 관리자 계정을 변경합니다.

메뉴별 상세 기능

1. 문서 검토

목적: 과정 안내, 규정 등 챗봇이 답변 근거로 사용할 자료를 등록하고 공개 여부를 결정합니다.

  • PDF를 Markdown 문서로 변환하거나, 이미 작성된 Markdown 문서를 바로 등록할 수 있습니다.
  • Markdown 내용을 FAQ JSON 형식으로 변환해 반복 질문 자료로 활용할 수 있습니다.
  • 파일명·문서명·변환 방식·버전·처리 상태를 목록에서 확인합니다.
  • 변환된 Markdown/JSON을 미리 보고 검토 메모를 남긴 뒤 승인 또는 반려합니다.
  • 문서를 삭제·복원하고, 검색 결과가 갱신되지 않을 때 FAISS 검색 인덱스를 수동 재생성합니다.

운영 기준: 내용 확인 없이 승인하지 않습니다. 인덱스 재생성은 수초~수분이 걸릴 수 있으며 완료 메시지까지 확인합니다.

2. FAQ 관리

목적: 자주 묻는 질문에 일관된 기준 답변을 제공하고, 표현이 조금 달라도 같은 FAQ를 찾도록 설정합니다.

  • FAQ ID, 분류, 질문, 답변을 새로 만들거나 수정·삭제합니다.
  • keywords, 별칭, 검색 힌트에 실제 이용자가 쓰는 유사 표현을 추가합니다.
  • source_files로 답변 시 함께 참고할 문서를 지정할 수 있습니다.
  • direct_answer를 켜면 조건이 맞는 질문에 해당 FAQ 답변을 바로 제공할 수 있습니다.
  • top_k로 답변 작성 시 확인할 문서 조각 수를 조정합니다.

운영 기준: 저장 후 원문 질문, 줄임말, 말투를 바꾼 질문으로 각각 시험합니다. 너무 넓은 키워드는 관련 없는 질문까지 같은 FAQ로 연결할 수 있습니다.

3. 프롬프트

목적: AI가 답변을 작성할 때 지킬 말투, 범위, 상담 처리 원칙을 관리합니다.

  • 규칙의 식별 키, 화면 표시명, 실제 지시문을 조회·추가·수정합니다.
  • 일반 상담, 취소·환불, 상담사 연결, 답변 실패 시 안내 등 상황별 규칙을 관리합니다.
  • 저장된 값은 데이터베이스에 남아 서버 재시작이나 재배포 후에도 유지됩니다.
  • 기본으로 보호된 핵심 프롬프트는 수정할 수 있지만 삭제할 수 없습니다.

운영 기준: 한 문장 수정도 전체 답변에 영향을 줄 수 있습니다. 변경 전 내용을 별도 기록하고 정상·민감·범위 밖 질문을 함께 시험합니다.

4. 로그/내보내기

목적: 이용자가 무엇을 물었고 챗봇이 어떻게 처리했는지 확인해 품질, 장애, 이용량을 분석합니다.

  • 시작일·종료일·세션 ID로 대화 로그를 검색하고 Excel로 내보냅니다.
  • 대화 시각, 처리 출처, LLM 비용, 질문과 답변을 확인합니다.
  • 처리 로그에서 문서 변환·인덱스 생성 등의 성공·실패 메시지와 상세 내용을 봅니다.
  • 감사 로그에서 관리자가 언제 어떤 대상을 변경했는지 확인합니다.
  • 세션 목록과 상세 화면에서 익명/로그인 여부, 시작·최근 시각, 메시지 수와 대화 흐름을 확인합니다.

운영 기준: 질문·답변에는 개인정보나 상담 내용이 포함될 수 있습니다. 내보낸 파일은 사내 승인된 위치에만 보관하고 외부 공유를 금지합니다.

5. 데이터 관리

목적: 챗봇 기본 테이블과 별개로 운영에 필요한 표 형태의 자료를 관리자 화면에서 관리합니다.

  • 이름과 설명을 정해 새 표를 만들거나 불필요한 표를 삭제합니다.
  • 문자·숫자·날짜 형식의 열을 추가하고 이름·순서·구성을 변경합니다.
  • 행을 추가·수정·삭제하고 CSV 또는 Excel 파일의 자료를 가져옵니다.
  • 선택한 표만 Excel로 내보내거나 모든 표를 하나의 통합 문서로 내보냅니다.

운영 기준: 가져오기 전 열 이름과 날짜·숫자 형식을 확인하고, 기존 표 삭제 전 반드시 Excel 백업을 남깁니다.

6. DB 브라우저

목적: 장애 조사나 데이터 확인을 위해 Aurora RDS의 실제 테이블 구조와 내용을 직접 살펴봅니다.

  • 전체 테이블의 열 수·행 수와 페이지별 데이터를 조회합니다.
  • 시스템이 허용한 일부 테이블만 행 수정·삭제가 가능합니다.
  • id, created_at, updated_at 같은 보호 열은 수정할 수 없습니다.
  • 로그·취소 요청·감사 로그·사용자 정의 표 등 허용 목록에 있는 테이블만 삭제할 수 있습니다.

운영 기준: 일반 콘텐츠 변경에는 사용하지 않습니다. 작업 전 대상·행 수·백업·복구 방법을 확인하고 개발자가 수행합니다.

7. 설정

목적: 답변 생성에 사용할 OpenAI 모델과 데이터 암호화 범위를 관리합니다.

  • 현재 사용 모델을 확인하고 OpenAI에서 조회한 사용 가능 모델을 지능·비용·속도 기준으로 비교해 변경합니다.
  • FAQ, 프롬프트, 문서의 암호화 여부를 설정합니다. 채팅 내용 암호화는 항상 적용되며 끌 수 없습니다.
  • 암호화 설정 변경은 이후 저장분에 적용됩니다. 기존 자료는 별도의 일괄 암호화 또는 복호화 작업이 필요합니다.
  • 데이터별 전체·암호화·평문 건수를 확인해 변환 진행 상태를 점검합니다.

운영 기준: 모델 변경은 저장 즉시 운영 답변에 적용됩니다. 한산한 시간에 대표 질문으로 품질·속도·비용을 확인하고 기존 모델명을 기록해 둡니다.

8. 권한 관리

목적: 관리자 페이지에 접속할 수 있는 회사 Google 계정을 관리합니다.

  • 현재 로그인 계정과 등록된 관리자 이메일, 각 관리자를 추가한 사람을 확인합니다.
  • 새 관리자 이메일을 추가하거나 더 이상 필요 없는 계정을 제거합니다.
  • ADMIN_EMAIL로 지정된 최상위 관리자는 삭제할 수 없으며, 최상위 관리자만 해당 이메일을 변경할 수 있습니다.
  • 최상위 관리자 변경 시 현재 세션은 종료되므로 새 계정의 로그인 성공 여부를 바로 확인합니다.

운영 기준: 세부 역할별 권한 분리는 없습니다. 등록된 일반 관리자는 대부분의 관리 기능을 함께 사용할 수 있으므로 필요한 회사 계정만 최소한으로 등록합니다.
