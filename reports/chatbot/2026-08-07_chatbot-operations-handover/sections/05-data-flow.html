전체 데이터 흐름과 데이터 구조

사용자 질문과 관리자 문서가 어떤 경로로 들어오고, 어느 저장소에 기록되며, 다시 답변에 어떻게 사용되는지를 정리합니다.

데이터 관리 원칙

운영 데이터의 기준은 Aurora RDS이며, 문서 파일과 검색 인덱스의 장기 보관은 AWS S3가 담당합니다. EC2에 있는 FAISS 인덱스는 빠른 검색을 위한 실행용 사본이며, 브라우저의 대화 기록은 현재 탭에서 화면을 복원하기 위한 임시 저장 정보입니다.

B

관리자 문서 데이터 흐름

새 자료가 업로드된 후 검토·승인·검색 인덱스 반영을 거쳐 사용자 답변에 사용되는 과정입니다.

01 문서 업로드관리자가 MD/PDF 파일과 제목·분류를 등록합니다.
02 파일 보관원본·변환 문서를 S3에 저장하고 문서 정보를 RDS에 기록합니다.
03 검색 단위 생성문서를 작은 구간으로 나누고 검색용 데이터를 만듭니다.
04 관리자 검토내용과 변환 결과를 확인합니다. 승인 전에는 운영 검색에 사용하지 않습니다.
05 승인·활성화승인된 버전을 현재 사용 문서로 표시합니다.
06 검색 인덱스 생성활성 문서·FAQ 전체로 FAISS 검색 목록을 다시 만듭니다.
07 운영·백업EC2에서 검색에 사용하고 동일 인덱스를 S3에도 보관합니다.

데이터 구조: 업무 영역별 주요 테이블

대화·상담 데이터

chat_sessions대화 단위의 시작 시각, 최근 시각, 메시지 수를 관리합니다.
chat_messages사용자와 챗봇의 실제 메시지를 순서대로 저장합니다.
chat_logs질문별 답변 방식, 검색 결과, 오류, 처리 상태를 분석용으로 저장합니다.
cancel_requests취소·환불·일정 변경 요청을 별도 목록으로 관리합니다.

관계 하나의 세션 ID에 여러 메시지·분석 로그·취소 요청이 연결됩니다.

문서·답변 기준 데이터

documents업로드 문서의 버전, 승인·삭제 상태와 S3 파일 위치를 관리합니다.
chunks문서별로 나눈 검색 구간과 해당 순서를 저장합니다.
faqsFAQ 질문·답변, 관련 단어, 사용 여부를 저장합니다.
prompt_configs상담 말투, 취소·연결·오류 안내 등 답변 작성 규칙을 저장합니다.

관계 문서 1건은 여러 검색 구간으로 나뉘며, 승인 문서와 FAQ가 FAISS 인덱스의 입력이 됩니다.

설정·관리 이력

app_settings현재 AI 모델, 홈페이지 최신 정보와 동기화 상태를 저장합니다.
admin_users관리자 접근이 허용된 Google 계정을 저장합니다.
admin_audit_logs관리자가 언제 어떤 내용을 변경했는지 기록합니다.
processing_logs문서 변환·검색 준비·승인 처리 결과를 기록합니다.

사용자 정의 데이터

custom_tables관리자 화면에서 만든 데이터 표의 이름과 설명을 저장합니다.
custom_columns각 표에서 사용할 열 이름·형식·순서를 저장합니다.
cdata_{id}사용자가 입력하거나 Excel에서 가져온 실제 행 데이터를 저장합니다.

관계 사용자 정의 표마다 별도의 실제 데이터 테이블이 생성됩니다.

저장 위치별 역할

저장 위치저장 데이터보존 성격운영 시 확인사항
브라우저 sessionStorage현재 탭의 대화 목록, 선택한 대화, 관리자 로그인 토큰브라우저 탭 단위 임시 정보브라우저 기록은 운영 DB의 대화 기록을 대체하지 않습니다.
Aurora RDS대화, 문서·청크, FAQ, 프롬프트, 앱 설정, 관리자·감사 로그운영 데이터 기준 저장소백업·복구와 암호화 키 관리가 핵심입니다.
AWS S3문서 원본·변환본·청크·임베딩 정보, FAISS 파일파일·검색 산출물 장기 보관버킷 권한과 경로 document-chatbot/을 유지합니다.
EC2 로컬실행 중인 FAISS 인덱스와 프론트엔드 빌드 파일서비스 실행용 사본서버 교체 시 S3 또는 RDS 기준으로 복원합니다.
외부 서비스OpenAI 요청·응답 처리, 공식 홈페이지 원본 조회, Google 인증API 호출 시 사용API 키·권한·비용·연결 실패를 별도로 관리합니다.

주요 작업이 남기는 데이터

작업새로 기록되거나 변경되는 데이터추가 처리
사용자가 질문chat_sessions, 사용자 chat_messages안전 검사와 답변 방식 선택
챗봇이 답변 완료챗봇 chat_messages, chat_logs관리자 통계·Excel 내보내기에 사용
취소·환불 요청cancel_requests + 일반 대화 로그채널톡 연결 버튼 표시
관리자가 문서 업로드documents, chunks, processing_logs, S3 파일검토 대기 후 승인 필요
문서·FAQ 승인/변경활성 상태, 관리자 감사 로그, FAISS 인덱스EC2 저장 후 S3에 인덱스 백업
모델·프롬프트·권한 변경app_settings, prompt_configs, admin_users, 감사 로그대부분 재배포 없이 다음 요청부터 반영

복구 우선순위: RDS는 운영 데이터의 기준이므로 정기 백업이 필요하고, S3는 문서와 검색 인덱스 복구에 필요합니다. ENCRYPTION_KEY가 없으면 암호화된 데이터의 내용을 복구할 수 없으므로 DB 백업과 별도로 안전하게 인계해야 합니다.
