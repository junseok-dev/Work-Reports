서비스가 움직이는 구조

첫 번째 그림은 챗봇을 구성하는 서버·저장소·외부 서비스를, 두 번째 그림은 사용자 질문이 답변으로 처리되는 과정을 보여줍니다. 각 구성요소의 역할을 먼저 표기하고 기술명은 보조 정보로 표시했습니다.

A

전체 시스템 구성 시스템 아키텍처

구성 개요: 사용자가 웹사이트에서 질문하면 AWS 애플리케이션 서버가 운영 데이터와 외부 AI 서비스를 사용해 답변을 반환합니다.

B

질문이 답변으로 바뀌는 구조 서비스 아키텍처

질문을 먼저 안전하게 확인하고, 저장된 답을 쓸지 문서를 찾아 AI가 설명할지, 상담 직원에게 넘길지를 결정합니다.

flowchart TB
  Q["① 사용자 질문 입력"] --> RECEIVE["② 서버가 질문 접수
질문 저장 · 최근 대화 확인"]
  RECEIVE --> GUARD{"③ 안전 검사
처리 가능한 질문인가?"}

  GUARD -->|"개인정보 · 공격 표현"| BLOCK["안전 차단 안내"]
  GUARD -->|"안전"| SENSITIVE{"④ 민감·책임 질문인가?"}
  SENSITIVE -->|"취업률 · 특정 회사 합격 등"| CAUTION["검증된 범위만 안내
필요 시 상담 연결"]
  SENSITIVE -->|"일반 질문"| ROUTE{"⑤ 답변 방법 선택"}

  ROUTE -->|"반복 질문 · 최신 일정"| FAQ["FAQ·일정 답변
저장된 기준 답변 사용"]
  ROUTE -->|"상세 설명 · 비교 · 추천"| RAG0["문서 검색형 답변
RAG 파이프라인 시작"]
  ROUTE -->|"취소 · 환불 · 사람 확인 필요"| HUMAN["상담 연결 처리
요청 기록 · 채널톡 버튼"]
  ROUTE -->|"서비스 범위 밖"| SCOPE["답변 가능 범위 안내"]

  subgraph RAG["⑥ RAG 상세 처리 · 문서를 찾아 답변하는 경로"]
