1. 최종 판정과 전체 흐름

원천·정제·파생 데이터 정의는 수정할 필요가 없다. 문제는 LMS-AI가 확정 계약보다 오래된 입력과 mock 조회 경로를 사용한 것이었고, 이번 작업에서 FE가 표시하는 직무 적합도·프로젝트·문제해결 3개 분석 계약으로 통일했다. 다만 실제 LLM 출력 2건이 후처리 검증에서 거절되어 최종 문장 품질은 아직 합격 처리하지 않는다.

2. 검증 결과

자동검사는 코드가 정해진 계약과 산식을 반복 가능하게 지키는지 본다. 사람 검토는 생성 문장이 맥락상 자연스럽고 과장되지 않았는지 본다. 이번에는 최종 출력이 자동 검증을 통과하지 못했으므로 사람 품질 점수는 산출하지 않았다.

97/97전체 회귀 테스트 100%
0건정제 ERROR
1건정제 WARNING
0/2실제 출력 수용
0회자동 재호출

비용 없는 자동검사

  • FE camelCase 요청·응답 계약
  • 평가 문항 배점 환산
  • 인증·개인 귀속·준비 상태
  • 생성 POST와 조회 GET의 동일 계약
  • 기존 mock 7블록 응답 차단

실제 호출 결과

  • 1차: 프로젝트 요약에 직무 전용 근거 코드 혼입
  • 2차: 직무 평가 근거와 중복 이론근거 목록 불일치
  • 두 결과 모두 저장·공개 전에 거절
  • 근거 필터와 중복 필드 제거를 코드에 반영
  • 비용 제한 때문에 추가 호출하지 않음
100%의 의미: 97/97은 코드 회귀검사 통과율이다. AI 정확도 100%가 아니다. 이번 최종 계약의 생성 품질은 수용된 결과가 없어 측정 보류가 맞다.

4. 분석에 들어간 근거

황수빈 FE mock을 정답으로 삼지 않고, 확정 데이터 계약을 실제처럼 통과시키는 단일 입력 사례로 사용했다. 원천에서 확인할 수 없는 개인 활동은 비워 두었고, 그 결과도 NOT_READY로 보존했다.

직무 적합도

  • 평가 6건의 문항별 배점·획득점수
  • 승인 자격 2건
  • 개인 담당 과업과 역할 패턴
  • 인증 문제해결 3건
  • 관심 직무·기술은 희망 문맥으로만 사용
READY자유 직무 1~3개

프로젝트

  • 인증 프로젝트 3건
  • 개인 프로젝트 1건: 담당 과업·최종 기여·연결 문제해결
  • 팀 프로젝트 2건: 개인 귀속 근거 없음
  • 팀 기술·팀 성과는 배경 문맥만 허용
  • 팀 전체 보드 수·개인 기술 추정·산출물 추정 제외
READY 1NOT_READY 2

문제해결

  • 상황·조치·검증 결과가 완전한 인증 사례 3건
  • 데이터·머신러닝·협업 카테고리
  • 평균 1.3일·중앙 1일
  • 독립 1건·지원 활용 2건

READY성장 점수 없음
유일한 경고: 개인 프로젝트가 인증 완료지만 진행 상태는 IN_PROGRESS로 남아 있다. 분석에서 제외하지 않고 상태 충돌을 제한사항으로 전달한다. ERROR는 0건이다.

5. LLM과 코드의 역할 경계

gpt-5.4-mini가 판단

  • 고정 목록 없는 직무·실무 역할 1~3개
  • 확인 근거와 직무 업무의 적합도
  • 프로젝트 개인 수행 설명과 한계
  • 문제해결 상황·조치·검증 요약

LMS-AI가 계산·검증

  • 평가 환산점수와 업무 건수
  • READY·PARTIAL·NOT_READY
  • 근거 코드 존재·허용 범위
  • 개인/팀 귀속과 개인정보 마스킹
  • 신뢰 수준과 이론 이해도
비용 절약 장치무료 전처리·계산·테스트 → 입력 해시 확인 → LLM 1회 → 실패 시 자동 재호출 금지이번 실패로 같은 사실을 모델이 중복 작성하게 한 필드는 제거했고, 다른 분석 영역의 근거가 섞이면 허용 영역만 남기도록 후처리 경계를 강화했다.

6. 직무 적합도 결과 상태

직무 후보를 7개 고정 직무에 끼워 맞추지 않는 계약은 유지됐다. 하지만 최종 계약에서 수용된 LLM 응답이 없으므로 직무명·순위·적합도 점수는 이번 보고서에 게시하지 않는다.

READY

입력 충분성

  • 평가·자격·개인 과업·문제해결 근거 존재
  • 관심 직무 외 후보도 자유롭게 도출 가능
  • 관심 직무 자체는 가점 근거가 아님
수정 완료

이론 이해도

  • 직무 후보가 실제 인용한 평가만 사용
  • 별도 평가 코드 복제 필드 제거
  • 0건 NOT_READY · 1건 PARTIAL · 2건 이상 평균
미측정

문장 품질

  • 수용 결과가 없어 정확도 % 미산출
  • 다음 1회 결과에서 근거 적합성 사람 검토
  • 점수는 취업 가능성으로 해석 금지

7. 프로젝트 분석 결과 상태

이번 계약 수정의 핵심이다. 프로젝트 3건을 모두 보여 주되 개인 수행 판단은 학생 UUID로 귀속되는 근거가 있을 때만 허용한다.

NOT_READY

상권별 매출 분석

  • 팀 도메인·기술·성과는 배경으로 표시 가능
  • 황수빈 담당 과업·최종 기여·동료 관찰 없음
  • 개인 역할·기술·성과 판단 금지
NOT_READY

시세 예측 모델

  • 팀 모델·성과는 배경으로 표시 가능
  • 황수빈 개인 귀속 근거 없음
  • 튜닝·API 성과를 개인에게 자동 귀속하지 않음
READY

채용 기술 스택 지도

  • 개인 담당 과업 4건·완료 4건
  • 최종 본인 수행 내용 존재
  • 연결 인증 문제해결 1건으로 교차 확인
준비 상태 산식직접 근거(담당 과업 또는 최종 기여) + 교차 근거(동료 관찰 또는 연결 인증 문제해결)둘 다 있으면 READY, 한쪽만 있으면 PARTIAL, 모두 없으면 NOT_READY다. 팀 전체 업무 수·팀 기술·팀 성과만으로 READY가 되지 않는다.
품질 판정: 입력과 계산 경계는 의도대로 바뀌었다. 다만 실제 생성 문장이 NOT_READY 프로젝트에서 개인 판단을 완전히 피하는지는 수용 결과가 없어 아직 미검증이다.

8. 문제해결 분석 결과 상태

상황·해결 과정·결과가 모두 있는 인증 사례가 1건 이상이므로 입력 상태는 READY다. 사례 수를 역량 점수나 성장률로 바꾸지 않는다.

표시 기준원천 카테고리 그룹이 주 결과 · 데이터 처리/모델 개선/인프라 보조 축은 점수 없음협업 사례처럼 고정 보조 축에 매핑되지 않는 사례도 원천 카테고리에서는 빠지지 않는다. 폐기된 문제해결 성장 분석은 생성하지 않는다.
품질 판정: 계산 가능한 건수·기간·독립 여부와 근거 원문은 충분하다. 최종 요약 문장의 정확도는 다음 수용 결과에서 확인해야 한다.
황수빈 1명의 FE 기반 구조화 입력으로 계약을 검증했다. 테스트 통과율은 코드·계산의 재현성을 뜻하며, 전체 수강생에 대한 AI 정확도나 취업 적합성을 의미하지 않는다.
