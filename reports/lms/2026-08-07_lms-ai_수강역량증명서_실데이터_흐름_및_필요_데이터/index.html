1. 실데이터 처리 흐름 — 2개 후보 비교 후 최종 택1

원천 처리와 S3 저장 방식은 같고 화면으로 제공하는 마지막 구간만 다르다. 후보 A는 Spring BE가 발급본을 동결하고, 후보 B는 FE가 FastAPI 결과를 직접 조회한다. 아래 두 구조 중 운영안 하나만 확정한다.

아키텍처 결정 필요: 두 그림은 병행 운영안이 아니다. 인증·권한·Snapshot 책임과 개발 범위를 비교한 뒤 후보 A 또는 후보 B 하나를 선택해야 한다.
후보 A 핵심: S3의 AI 분석 데이터는 하나의 영역이며 입력·결과 객체만 구분한다. FastAPI 처리 후 Spring BE가 전체 데이터를 취합·승인하고 발급본을 동결한다.
후보 B 핵심: S3의 AI 분석 데이터는 하나의 영역이며 입력·결과 객체만 구분한다. Spring BE 없이 FE가 FastAPI의 최신 결과를 직접 받는다.

2. 이번 설계의 기준

S3 저장소는 1개증명서 탭·AI 분석·파생데이터 3개 영역으로 나누고, 증명서 탭 영역은 기수 ID·수강생 UUID·버전 아래 6개 폴더로 구성한다.
항목별 상태 유지데이터가 없더라도 탭과 섹션을 유지하고 상태 메시지를 표시한다.
상담노트 제외운영 DB·S3·FastAPI·증명서 화면의 현재 범위에 두지 않는다.
운영 연동 구조는 택1두 도식은 비교 후보이며, 운영 전 Spring BE 경유형 또는 FastAPI 직접형 중 하나를 확정한다. 두 경로를 동시에 운영한다는 의미가 아니다.

6. AWS 구현 현황 — 전체 흐름에서 어디까지 왔나

AWS는 데이터 처리 단계를 추가하는 것이 아니라 FastAPI를 실행하고 데이터를 보관하는 기반이다. 현재는 컨테이너·배포 정의까지 준비됐고, 실제 ECS 상시 실행과 S3 실데이터 연결부터는 남아 있다.

ECR · 프로그램 이미지 보관FastAPI 소스와 실행 환경을 묶은 Docker 이미지를 저장한다. 수강생 데이터는 저장하지 않는다.
ECS/Fargate · FastAPI 실행ECR 이미지를 태스크로 실행해 파생 계산·AI 분석 API를 제공한다. 결과 영구 저장소는 아니다.
S3 · 증명서 데이터 보관기수·수강생·버전별 정제 데이터, 파생데이터와 AI 분석 데이터를 저장한다.

AWS 구성현재 판정확인된 내용앞으로 남은 작업
Docker 이미지구현됨Python 3.12·FastAPI·포트 5177·/health를 포함한 Dockerfile과 로컬 smoke 기록이 있다.fixture가 포함된 현재 이미지를 실데이터 Repository 기반으로 전환하고, 운영용 이미지의 커밋 SHA·digest를 고정한다.
ECR현재 상태 미확인lms-ai 저장소와 초기 이미지 생성 기록, GitHub Actions의 SHA·latest push 단계가 있다.저장소·현재 이미지 digest를 AWS에서 재확인하고 최신 이미지를 push한다. 이미지 수명주기 정책도 설정한다.
ECS 태스크 정의정의 준비됨Fargate x86_64, 0.25 vCPU·512MB, 포트 5177, Secrets Manager 주입, CloudWatch 로그 설정 파일이 있다.태스크 정의의 wget 헬스체크는 현재 이미지에 해당 도구 설치가 없어 실패할 수 있다. Dockerfile과 같은 Python 기반 검사로 통일한 뒤 새 revision을 등록한다.
ECS 클러스터·서비스실행 여부 미확인클러스터와 태스크 정의 생성 기록은 있으나 ECS 서비스, desired/running count, 현재 revision은 확인되지 않았다.서비스를 생성 또는 재확인하고 desired count를 설정한 뒤 태스크가 안정적으로 유지되는지 검증한다.
IAM·Secrets Manager일부 준비 기록실행 역할과 OpenAI 키 secret 생성·주입 기록이 있다. 현재 태스크 정의에는 execution role만 있다.ECR pull·로그·secret 권한을 재검증한다. FastAPI가 S3를 읽고 쓸 수 있도록 최소 권한의 별도 task role과 taskRoleArn을 추가한다.
VPC·보안그룹·호출 경로미확정Spring BE가 내부 FastAPI를 호출한다는 방향만 정해져 있다.기존 BE VPC의 private subnet을 우선 재사용하고, 보안그룹·내부 DNS/Service Connect 또는 내부 ALB 중 한 가지를 확정한다. OpenAI 호출용 outbound 경로도 확인한다.
S3미구현이 보고서의 1개 저장소·3개 논리 영역·기수/수강생/버전 구조는 목표 설계다.버킷·prefix, 암호화, 버전 관리, 보존 정책, manifest를 확정하고 전처리 업로드 및 FastAPI S3 Repository를 구현한다.
CloudWatch설정 준비됨/ecs/lms-ai 로그 그룹 생성 기록과 awslogs 설정이 있다. 실제 로그 유입은 확인되지 않았다.실행 로그·오류 추적을 확인하고 보존 기간, ECS unhealthy/재시작, 5xx 알람을 설정한다.
GitHub Actions워크플로 준비됨develop에서 ECR push 후 ECS 롤링 배포하는 workflow가 있다. DEPLOY_ENABLED=true일 때만 실행된다.AWS·GitHub 변수와 secret 상태를 확인해 배포를 활성화한다. 장기 access key는 가능하면 OIDC 역할로 전환하고 롤백을 시험한다.
실데이터 E2E미구현DB→S3→ECS FastAPI→Spring BE→FE 전체 성공 기록이 없다.수료자 1명 기준으로 추출·전처리·AI 분석·Snapshot 동결·화면 표시와 데이터 없음 상태까지 종단 검증한다.

7. 현재 구현 상태 — 실데이터 통합 연동

2026-08-07 로컬 코드 기준이다. AWS 실행 기반과 별도로 운영 DB 원천이 증명서 화면까지 연결되는 데이터·서비스 구현 상태를 정리한다.

FE 증명서 화면일부 구현

증명서 7개 탭 화면은 있으나 운영 실데이터가 아니라 mock·fixture 중심이다.

운영 DB 추출미구현

수료 트리거, 증명서 원천 조회와 수강생 단위 데이터 취합이 구현되지 않았다.

데이터 전처리미구현

Parquet 변환, 타입 통일, 검증·정규화와 데이터 없음 상태 생성이 구현되지 않았다.

S3 데이터 연동미구현

기수·수강생·버전별 저장, manifest와 FastAPI S3 Repository가 구현되지 않았다.

AI 분석 실데이터 연결골격만 구현

분석 API는 있으나 S3 정제 입력 조회, AI 허용 필터와 분석 결과 저장은 구현되지 않았다.

Spring BE Snapshot미구현

분석 요청·완료 수신, S3 전체 취합, 검토·승인과 CertificateSnapshot 동결이 없다.

FE 실데이터 전환미구현

선택한 운영 연동안의 실응답 연결, 데이터 없음 상태와 런타임 mock 제거가 남았다.

전체 E2E미검증

DB→S3→FastAPI→선택한 제공 경로→FE 흐름을 실제 수료자 기준으로 검증해야 한다.

8. AWS를 포함한 남은 작업 순서

필드 계약 확정
7개 탭 필드와 운영 DB 원천, 필수·선택·공개·AI 허용 범위를 연결한다.
추출·전처리 구현
수료 트리거, DB 조회, Parquet 변환, 검증·정규화를 구현한다.
S3 정책 확정
파티셔닝, manifest, 파일 크기, 버전·재처리·보존 정책을 정한다.
FastAPI 실연결
S3 조회, 파생 계산, AI 허용 필터, 작업 상태와 결과 저장을 구현한다.
ECR 이미지 확정
헬스체크를 수정하고 현재 소스를 SHA 이미지로 빌드·push해 digest를 확인한다.

배포·관측 검증
Actions 배포를 활성화하고 CloudWatch 로그·알람·롤링 배포·롤백을 시험한다.
BE Snapshot
완료 알림 뒤 S3 입력+결과를 취합하고 검토·승인·공개 payload를 동결한다.
FE 전환·mock 제거
Spring BE Snapshot만 조회하도록 연결하고 런타임 mock·fallback을 제거한다.
